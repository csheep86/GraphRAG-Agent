## 1. 系统概览

### 1.1 定位

面向**私有化部署**的多模态企业知识库平台。核心链路：多模态文档解析 → 实体关系抽取与知识图谱构建 → 图谱增强检索问答（GraphRAG）→ 可溯源引用。典型落地业务域为**财务关联交易识别**与**考勤合规**。

### 1.2 逻辑拓扑

```
浏览器 ──HTTPS──> Next.js 前端 (3000)
                     │ fetch (同源/代理)
                     ▼
              FastAPI 后端 (8000)
        ┌────────────┼─────────────┬──────────────┐
        ▼            ▼             ▼              ▼
  PostgreSQL 16   Neo4j 5.26   文件存储     外部 LLM / MinerU
  (元数据/权限   (图谱)      (本地 FS)     (出向受控，可切内网)
   /审计/任务)
```

### 1.3 部署形态

一条 `docker compose up` 起全套。**一套 compose = 一个租户**的资源与隔离边界。支持变体（`deploy/variants/`），当前提供 `baseline` 与 `internal-demo` 两个形态。

### 3.5 异步任务机制

**不是** Celery / RQ / Redis 队列（依赖表中无任何 broker，无 worker 进程）。

| 机制 | 实现 |
|---|---|
| 载体 | FastAPI `BackgroundTasks`（`tasks/manager.py:58-60`） |
| 状态持久化 | PostgreSQL（`documents.status` / `affiliation_tasks.status`），**严禁**内存字典 |
| 幂等 | `submit()` 校验非 `pending/processing` 不重投 |
| 并发控制 | 模块级 `asyncio.Semaphore`（默认 2） |
| 重试 | tenacity `AsyncRetrying`，最多 3 次，初始 1s 指数退避；仅重试 Timeout/Connection/OSError/httpx 错误；次数回写 DB |
| 孤儿回收 | 启动时 `recover_orphan_tasks()` 逐租户把 `pending/processing` 置 `failed` + `error_code=TASK_INTERRUPTED` |
| 注册任务 | `document.parse` / `document.extract` / `kg.build` / `risk.detect` / `affiliation.detect` |

> ⚠️ **真实缺口（代码自述，`registry.py:17-20`）**：**管线阶段之间无自动接续**。上传只提交首个阶段，后续阶段需由脚本或人工按序驱动。根因：TaskManager 依赖请求级 BackgroundTasks，请求结束即失效。

### 4.2 Neo4j 图模型

- 节点：`Entity`（`canonical_name` / `aliases` / `confidence` / `pii_flags` / `org_id` / `kg_version`）、`Evidence`（文本块证据）、另含业务节点（考勤/关联域的事实记录）。
- 关系：带 `kg_version` 属性；全部节点与关系均带 `org_id`。
- 所有查询按 `kg_version` 过滤，仅 `active` 版本对外可读。

### 4.3 一致性策略

**PostgreSQL 为 Source of Truth，先 PG 后 Neo4j + 补偿**：

1. `kg_versions` 先落 `writing`；
2. 写 Neo4j（`MERGE` 幂等）；
3. 成功置 `active`，失败置 `failed` 且**不对外提供**；
4. 查询层只认 `active`，**不允许幽灵版本**。

### 4.4 存储抽象

`storage/base.py` 定义键抽象，`local_fs.py` 为唯一实现。`storage_key` 以 `org_id` 为前缀并做越权校验。S3/MinIO/OSS **零代码**（`storage/__init__.py:8-10` 明确 by design，故意不做 stub）。

### 5.3 数据层与 Mock 机制

架构：`page / store → src/api/* → src/api/client.ts → fetch`（或走 `src/api/mock/*`）。

- HTTP 客户端为**手写 fetch 封装**（`client.ts`），非 openapi-fetch。`cache: "no-store"`，FormData 不设 Content-Type，dev 环境注入 `X-Org-Id`。
- `ApiError` 承载契约统一的 `code` / `status` / `trace_id` / `detail`。
- **无重试、无拦截器、无 token 刷新、无请求取消、无 SSE/流式**（全仓 `EventSource|WebSocket|getReader|stream` 搜索结果 0 条）。

> ⚠️ **Mock 开关是部署红线**：`USE_MOCK = process.env.NEXT_PUBLIC_USE_MOCK !== "false"`，即**默认全 Mock**。
> `USE_MOCK=false` 时，只有命中 `CONTRACT_COVERED_PATTERNS`（21 条正则白名单）的端点走真实 HTTP，其余仍走 Mock —— **漏登记 = 静默假数据**。
> 生产/演示部署**必须**设 `NEXT_PUBLIC_USE_MOCK=false`，并确认白名单覆盖所需端点。

Mock 数据的真伪成分（影响"UI 上看到的是不是真的"）：

| Mock 文件 | 性质 |
|---|---|
| `compliance.ts` / `anomaly.ts` | 真机返回照录（2026-09-28 实跑） |
| `ontology.ts` | 真机候选快照；动作回显的 kg_version **刻意标注"未接后端"** |
| `policy-qa.ts` | 半真：`reasoning_path` 真机产出，`answer`/`confidence` 为占位 |
| `affiliation.ts` / `audit.ts` | 刻意造假（"示例甲/示例乙"、保留网段 IP、`?mock=1`），一眼可辨 |
| `documents.ts` / `graph.ts` | 构造数据（`MOCK_DOCUMENT_TOTAL = 1248` 为设计稿固定值） |

### 5.4 类型来源

`src/types/api.d.ts`（约 210KB）由 `npm run gen:api` 从 `contracts/openapi.yaml` 生成，`Path` 与 `components["schemas"]` 直接消费。另 `src/types/mock.d.ts` 为 Mock 层手工视图类型。

> ⚠️ 仓库内**无 CI 校验**两者与契约一致，属技术债。

## 6. 安全与合规

### 6.1 认证

Bearer JWT（`core/token.py`，HS256）。开发态兜底头 `X-Org-Id` / `X-Actor-Id` 仅在 `allow_dev_org_header=true` 且非生产生效。**无匿名路径**。

`POST /auth/login` 校验本库 `users` 表口令：租户由账号推导（**严禁**来自 body/query）、失败一律 401 且不区分原因（防账号枚举旁路）、首次成功登录回填 `activated_at`（席位计数唯一来源）。**不做 SSO**（`routes/auth.py:14-15` 明写为顺延项）。

### 6.2 授权（RBAC）

12 类资源 × 读/写矩阵，三类角色，`doc_scope` 支持文档级粒度。执行点在 `dependencies=`，路由体之前；拒绝返回 403 + `permission.denied` 留痕。

### 6.3 租户隔离（三层）

| 层 | 机制 | 说明 |
|---|---|---|
| PostgreSQL | **RLS**：14 张租户表 `ENABLE` + `FORCE` + 策略（`org_id = nullif(current_setting('app.current_org', true), '')::uuid`） | 每事务经 `after_begin` 重放 GUC（`SET LOCAL` 语义）。未绑 org ⇒ 谓词 NULL ⇒ **0 行 fail-closed** |
| 应用账号 | 受限角色 `app_rls`（`NOBYPASSRLS`，非超级用户、非表 owner） | 超级用户会绕过一切 RLS，禁止使用 |
| 应用层 | 所有查询显式传 `org_id`；`system_session()` 为唯一刻意不绑 org 的通道 | 这是 ADR-0003 裁决的**常设防线**，不因 RLS 生效而移除 |
| 图谱侧（Neo4j） | 节点/关系全量带 `org_id` + `validate_kg_version_tenant_boundary` 校验；跨 org ⇒ 403 `KG_TENANT_LEAK` | **Neo4j 社区版没有 RLS**，应用层是**唯一**防线 |

### 6.4 出向管控（私域部署）

`core/egress.py` 在**构造客户端之前**阻断（而非发出去再判），白名单精确匹配 `host[:port]`（不含通配），内网与回环天然放行，违规落审计。开关关闭时零副作用。

### 6.5 脱敏

loguru patcher `mask_log_record` 在落地前脱敏 `logger.bind` 的 extra 字段，覆盖合同金额、发票号、税号、法人、银行、身份证、电话、文件名等八类策略，共 144+ 调用点。

> ⚠️ 不覆盖日志 `message` 正文原文与未登记 key —— 属已知缺口。

### 6.6 限流

slowapi 60 次/分钟/IP；`/health` 豁免；429 带 `Retry-After`。当前存储为 `memory://`（单机），切 Redis 只需改一处。

### 6.7 审计与可追溯

所有请求成功/失败落 `audit_log`（actor、IP、资源、document_id、耗时、outcome）；全链路 `trace_id` 贯穿并在所有响应（含 CORS 预检）回显；前端支持按 trace_id 回放整条调用链。

### 6.8 License 控权

Ed25519 签名验证 + 机器指纹 + 四维度（租户数 / 席位数 / 功能模块 / 有效期）组合校验 + 宽限期；`LicenseMiddleware` 全局拦截，`/license/status` 与 `/health` 豁免；6 个 `LICENSE_*` 错误码进契约；离线签发第一步由 `backend/scripts/license_cli.py fingerprint` 提供。

## 7. 契约与集成

### 7.1 OpenAPI 契约治理

`contracts/openapi.yaml` 为**唯一真源**，由 Pydantic 模型导出（`scripts/export_openapi.py`），`app.openapi` 被替换为 `build_openapi(app)`。前端经 `gen:api` 生成 TS 类型。CI 的 contract job 校验零漂移（`--check` + `gen:api` 后 `git diff --exit-code`）。

**版本语义**（商业承诺的技术基础）：

| 段 | 递增时机 | 契约约束 |
|---|---|---|
| MAJOR | 架构代际更替 | 允许打破；**插件需重做** |
| MINOR | 功能版本 | 契约只加不改；接缝签名不变 |
| PATCH | 补丁 | **契约零 diff + 接缝签名快照逐字相同** |

### 7.2 集成接缝

8 个插件式接缝 + 1 个 License 接缝，每个接缝的实现集合必须**恰好等于** ADR-0004 §2.1 登记集合（不多不少），由 `scripts/check_seams.py` 机械校验。

| 接缝 | 接口 | 当前实现 |
|---|---|---|
| 1 身份源 | `AuthProvider` | `LocalAuthProvider`（**唯一**；SSO/AD/LDAP 未实现） |
| 2 摄入源 | `IngestionSource` | 0 实现 |
| 3 LLM | — | `build_chat_model()` 统一入口（作用于问答/抽取/本体建议三条路径） |
| 5 事件出口 | `EventSink` | `db` + `log` 两个本地实现（**唯一例外，允许 2 个**） |
| 6 导出 | `ExportSink` | `JsonCsvExportSink` |
| 9 License | `LicenseProvider` | `DevLicenseProvider` |
| 其余 | 存储 / 出向 / 评测 | 见 ADR-0004 §2.1 |

**接缝纪律**：新增实现必须**先扩写 ADR-0004 §2.1 登记行、再改门禁脚本**，漏任一侧 CI 必红。

### 7.3 插件式交付

构建期烘焙（`Dockerfile` `COPY plugins ./plugins`，compose `build.context` 为仓库根），**禁止运行时热插拔**。单一代码库 + `deploy/variants/*.yaml` 变体配置。定制分 L0 配置 / L1 适配器 / L2 业务定制三档。当前已落 `plugins/json-csv-export/plugin.yaml`（**真实插件**，`entry_point` 指向已投产实现并有"可导入"断言）。

**语言路线**：坚持 Python，**不换 Java**（理由：`langchain-openai` 为核心的 LLM/RAG 生态不可替代）。

## 8. 测试与质量门禁

### 8.1 测试规模与形态

`backend/tests/` 下 105 个 `test_*.py` + `conftest.py`。CI 实测 **997 通过 / 5 跳过 / 2 预期失败**（2026-10-06）。

> ⚠️ **本地口径 ≠ CI 口径**：本地无 Neo4j 时 8 条真图用例静默 skip（本地 991 passed / 11 skipped）。**验收一律以 CI 为准**。

`local_only` 标记注册在 `pyproject.toml:51-57`，目的是让 CI 单独跑一遍并打印 skip 原因，防止"看着绿、其实没跑"。不存在大规模 xfail/skip 掩盖未实现的情况。

### 8.2 CI 流水线（4 个 job）

| backend | `postgres:16-alpine` + `neo4j:5.26-community` | ruff + pytest（G-8 保证跑在 PG 上）+ 迁移等价性 + 评测门禁 |
| frontend | — | ESLint + TypeScript + 契约生成物零漂移 |
| contract | — | `export_openapi.py --check` + `gen:api` 后 `git diff --exit-code` |

### 8.3 护栏清单（G-1 ~ G-26，节选关键项）

| 护栏 | 拦什么 |

| G-2 | 接缝纪律：登记外实现 / 少做 / 预留字段泄进契约 / 文档与门禁不同步 |

## 10. 已知限制与技术债

| # | 限制 | 影响 |
|---|---|---|
| 1 | 管线阶段之间无自动接续 | 上传后需脚本/人工驱动后续阶段 |

## 11. 附录

### 11.1 术语

| 术语 | 含义 |
|---|---|
| `task_id` | 异步任务唯一标识（UUIDv4） |
| `trace_id` | 全链路追踪标识，跨模块一致，响应回显 |
| `kg_version` | 知识图谱版本号；只允许 `active` 版本对外可读 |
| `org_id` | 租户标识；**严禁**来自 body/query |
| `doc_scope` | RBAC 文档级粒度 |
| GraphRAG | Graph Retrieval-Augmented Generation |
| RLS | Row Level Security（PostgreSQL 行级安全） |
| fail-closed | 校验失败时按最严格方式处理（0 行 / 拒答），而非放行 |

### 11.2 错误响应规范

统一 JSON：

```json
{ "code": "STRING_CODE", "message": "人类可读", "detail": { }, "trace_id": "uuid" }
```

HTTP 状态码与业务 `code` 分离。异常处理器屏蔽回显 `input` / `ctx` / `url`。

### 11.3 验收建议

对本说明书所述能力的技术验收，建议以 `02-签约功能清单.xlsx` 的"验收方式"列为准，
并按 §6.3 的三层隔离、§5.3 的 Mock 开关、§9 的部署检查做专项复核。
