## 6. 已知限制（v1.1.0 待办）

完整清单与依据见 `backend/CODEBUDDY.md` §4，摘要如下。

**A. 架构性未实现**

1. PostgreSQL RLS + `SET LOCAL app.current_org` 未实现；SQLite 下仅由应用层 `org_id` 过滤兜底（ADR-0003 §3.1/§3.2）
2. `kg_versions` PG 真源表未建；版本状态机暂落 Neo4j `(:KgVersion)`（ADR-0002 §2）
3. M3 完整 Agentic-RAG 缺失：无 Tool 调用循环、无 chunk 级引用反查（M3 §4）
4. 文件写入存储抽象层缺失：只落 PG 元数据，`storage_key` 恒为 NULL（M1 §4.3）

**B. 数据质量**：E1 财务指标孤立节点（12/16 无任何边，图谱连通性差）；E2 实体命名可疑（需 Prompt 抽取规范重设计，Prompt 改动须版本化）

**C. 疑似缺陷**：B1 `Document.retry_count` 列存在但 executor 从不更新；B4 `Settings.task_retry_multiplier` 已声明但从未被消费；`_refuse()` 构造的拒答响应体未注入 `trace_id`

**D. 租户隔离**：`/agent/query` 缺 PG `documents` 表前置租户校验，Cypher `_QUERY_ALL_ENTITY_SUBGRAPH` 为 fail-open

**E. 联调遗留**：`scripts/import_to_neo4j.py` 不创建 `:Document` / `:Chunk` 节点（设计决定，待 v1.1.0 接入 MinerU + LangExtract 后填）；前端 `uploadDocument` 成功后未刷新列表

## 7. 升级与回滚

- **升级**：本版为 main 上的里程碑合并，无数据库迁移脚本；`documents` 仍为 SQLite（仅 `development` / `test`，production 检测到 SQLite 驱动会直接启动失败）
- **回滚**：优先 `git revert -m 1 <merge-commit>`（保留历史）；未推送时可 `git reset --hard v0.3.0^{commit}`
- **tag 重打**：`git tag -d v1.0.0` → `git push origin :refs/tags/v1.0.0` → 重新 `git tag -a` 并推送（annotated tag 无签名，可安全重打）
