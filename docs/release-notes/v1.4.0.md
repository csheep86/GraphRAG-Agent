### 7.5 ~~`graph/overview` 的 `entity_count = 0`~~ —— ✅ **已修（2026-09-26，随 v1.4.0 tag 重打纳入）**

**原症状**：演示剧本第 2 步「看图」时 `entity_count` 为 0（图谱有节点、只有计数是 0）。

**根因（只读排查确定，非数据问题）**：`app/services/graphs.py::_fetch_graph_overview_stats` **直接 `return {"doc_count": 0, "entity_count": 0, "relation_count": 0}`**，注释写着「实际实现见 `GraphOverviewRoute._load_stats_from_pg()`」——而 `app/api/v1/routes/graph.py` **根本没有该方法**，且 `fetch_graph_overview` 手里的 `db` **没往下传**。三个计数因此**恒为 0**。

**定性**：这不是"数据缺失"，是**静默假数据**——返回 0 冒充统计值。合规占位必须**显式报错**（如 `log_export` 抛 `NOT_IMPLEMENTED`），给 0 属项目纪律要拦的"假做"。

**修复**：
- 统计值接 PG 真源：`entity_count` / `relation_count` 取 `KgVersioningService(db).get_by_version(...)`（建图时 `mark_ready` 回填），**不**走 Cypher `count(n)`（免一次全表扫描）；
- `doc_count` = **`kg_version_id` 指向当前 active 版本（`kg_versions.id`）的文档数**——**不**把历史版本文档混进 active 视图（ADR-0002 §3.2：只读 active、严禁静默降级）。真机两种口径差异：严格 **6** / 宽松（`IS NOT NULL`）7，取严格；
- 真源缺失（无该版本行 / 漏传 `db` / `org_id`）→ **显式抛**（`NoActiveKgVersionError` 转 409 / `ValueError`），**绝不静默 0**。

**真机证据（真实 `dev.db`，¥0）**：active `v-s71a-fe1c4dc3` → **`doc_count 6 / entity_count 2000 / relation_count 819`**（修复前恒 0）；漏传 `db` → `ValueError`。

**教训（一并登记）**：原有用例把整个 `fetch_graph_overview` **打桩**了，硬编码 0 因此**测不出来**（392 passed 照样红不了），只有真机能暴露 ⇒ 已补 3 例直测统计真源（`tests/test_graph_overview_and_entity.py`），并把 conftest 的 `get_active` 桩**成对**扩到 `get_by_version`（否则"Neo4j 不可达"用例会因统计真源缺失被误判成 409）。

### 7.5.1 真机点验（Docker / Neo4j 起后补做）—— ✅ 通过，并**又抓出 2 个真机 bug（均已修）**

上一版 notes 里 §7.5 只有「真实 `dev.db` + 改后代码路径」的证据（Docker 没起）。**本次真机点验补齐**：`docker start neo4j` + `uvicorn` 起服 + 真实 HTTP 打 `127.0.0.1:8000`。

| 步骤 | 端点 | 真机结果 |
|---|---|---|
| 起服 | `GET /api/v1/health` | `status=ok` / `version=1.4.0` / `database=up` |

**点验中抓出并已修的 2 个真机 bug**（都与 §7.5 同类：**只有真机跑得出来**，pytest 全绿照样红不了）：

1. **`GET /entities/{id}` 的 Cypher 聚合函数嵌套**：`count(collect({rel: r, neighbor: n})) > $neighbor_limit AS has_more` —— Neo4j 直接 `SyntaxError`（*Can't use aggregate functions inside of aggregate functions*），被 `except Exception → GraphUnavailableError` 包成 **501「图谱不可用」**——把**语法错**伪装成**基础设施故障**（演示第 3 步「点实体」必现 501）。修：拆成两段 `WITH`，先 `collect(...) AS all_neighbors`，再 `all_neighbors[0..$limit]` + `size(all_neighbors) > $limit`。加静态守卫用例（测试库无 Neo4j，编译期拦不住，只能静态断言禁嵌套聚合）。
2. **实体属性名错配**：`kg/builder.py` 写的是 `n.entity_type`，而读侧三处全读 `properties["type"]`——真库**根本没有** `type` 属性 ⇒ `entity_type` **恒空**、`category` **恒兜底 `topic`**（演示第 2 步「看图」全节点一个颜色、第 3 步类型列空白）。修：新增 `_entity_type_from_properties()`（`entity_type` 优先、`type` 仅旧数据兜底），三处读侧统一改；分类表补**英文枚举**映射（`ORG` / `LEGAL_PERSON` → `org`，`REGULATION` / `CONTRACT_CLAUSE` → `norm`——真实抽取链路落的是英文枚举，原表只有中文 M4 mock 词）。**真机复验**：概览分类分布 **`org=264 / topic=236`**（此前全 `topic`）、类型分布 `ORG=264 / DATE=192 / MONEY=22 / PERSON=22`（此前全空）；实体详情 `type='ORG' category=org`。

> 注：写 `_entity_type_from_properties` 时我一度加了 `str()` 强制转换，被既有用例
> `test_fetch_document_subgraph_raises_on_contract_mismatch[entity-type-not-str]` 抓到——
