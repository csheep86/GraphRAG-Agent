## 6. 已知限制与降级登记（后续 Sprint 待办）

> 按 §4.4 纪律显式登记，**不伪装为已达成**。

### 6.1 证据粒度是 chunk 级，不是实体提及级（→ S10）

真机 10/10 条的 `evidence.text` 与 chunk 全文**等长**（`ev_len == chunk_len`，`index_of=0`）——证据取的是整段 chunk。若照 `splitHighlight` 渲染会把**整段原文全部标黄**，等于「高亮了几千字」= 没有高亮且**误导**。

**本版处置**：整段场景改**淡底 + 标注**「证据粒度为原文片段（chunk 级）；实体提及级定位待 Sprint 10」；只有片段是全文真子集时才 `<mark>` 高亮。**未伪造片段级高亮**。影响范围仅呈现方式，不影响「点击证据回原文」这一验收点。

### 6.2 `Citation.char_offset` 恒为 0（→ S10）

承 v1.2.0 §6.2 未变；片段级定位按 `plan.md:619` 归 S10，本版未做。

### 6.3 chunk 原文含未清洗的 HTML 表格标记（→ S10）

浏览器点验新发现：抽屉内 chunk 原文混有 `<table>` / `<tr>` / `<td>`（年报表格被解析为 HTML 后未转纯文本）。属**解析层数据质量问题**（批次 A / S6 链路），**不归前端修**；前端按原文原样展示，未做任何「美化」（不伪造干净文本）。随 S10 数据质量欠账一并处理。

### 6.4 `unaligned_subjects` 只建表不写（→ S9，缺口 **S7.2-1**）

表已建（spec §4.5），写入点随 S9 批次 D 的四源对齐落地。

### 6.5 `TaskManager.list_in_flight_task_ids()` 仍只扫 `documents`（缺口 **S7.2-2**）

`recover_orphan_tasks()` 已扩到扫 `affiliation_tasks`，但 `list_in_flight` 未同步——重启回收路径**不受影响**（后者才是 ADR-0001 的硬要求），差异仅在于「运行中任务列表」查询面，随 S9 一并补。

### 6.6 M4 算法与对齐率未完（→ S9）

连通分量 / 环路 / 金额不一致**三类算法未做**（本版只有共享法人 + 共享地址两类规则）；spec §3 验收 1 的四源对齐与 **0.95 对齐成功率未做**。

### 6.7 准入指标未测量（→ S13）

C1（图谱增益 ≥ 10%）/ C2-a（召回 ≥ 0.80）/ C2-b（误报 ≤ 0.15）**均未测量**——演示数据集既非 spec 的「200 合同 + 500 发票 + 100 凭证 + 20 组植入样本」，评测脚本也**待建**。本版 10 条疑点**不等于通过 spec §3 验收 6**。

### 6.8 事件只落不派（→ 待 M5 告警中心）

`dispatched_at` **恒 NULL**；四个事件类型中**只发** `risk.suspect_created`，`document.parsed` / `kg.updated` / `qa.answered` **只定义取值、不发送**（无真实触发点，发即假事件）。不做派发 / 重试 / webhook；未新增 `settings.*` 配置；未改 ADR-0004 §2.1（第 5 行已含 `db` / `log`）。
