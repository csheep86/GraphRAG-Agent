## 2. P7-E 专项：**换域名 / IP 不再需要重建镜像**（审计 B4 / B6）

**之前的口径**：`NEXT_PUBLIC_*` 在 `next build` 时被内联成立面量（交付脚本还把地址当 build-arg 烧进去），
现场换地址只能 `docker compose build`（分钟级）。

**现在的三层**：

1. `frontend/entrypoint.sh`：容器**每次启动**把 `NEXT_PUBLIC_API_BASE_URL` 写成 `public/env.js`；
2. `app/layout.tsx`：`<Script src="/env.js" strategy="beforeInteractive" />` —— 必须早于业务 bundle，否则会用旧地址闪一次；
3. `client.ts::runtimeApiBaseUrl()`：**运行时 > 构建期 > 内置默认**。

**真机读数**（本机 Docker 29.7.2，同一镜像 `docker run` 双对照）：

| 对照 | `NEXT_PUBLIC_API_BASE_URL` | `/env.js` 实际返回 |
|---|---|---|
| A | `http://127.0.0.1:8000` | `http://127.0.0.1:8000` |
| B | `http://192.168.10.77:8000` | `http://192.168.10.77:8000` |
| B 容器 `restart` 后 | 同上 | 同值（容器重启会重新生成） |

⇒ **未重建镜像，只改环境变量即生效。**

**⚠️ 一个必须说清的差别**（判据原文写的是 `restart`，实测并不成立）：

| 动作 | 是否应用新 env | 耗时 |
|---|---|---|
| `docker compose restart` | **否**（restart 复用容器原有配置） | 秒级 |
| `docker compose up -d frontend` | **是**（recreate 容器，**不是**重建镜像） | 秒级 |
| `docker compose build frontend` | 是（重新构建镜像） | 分钟级 |

客户的正确操作是**改 `.env` 后 `up -d`** —— 仍然不需要 build。这点已写进 `deploy/README.md` 与根 README。

**R18 红线没有被放松**：`NEXT_PUBLIC_USE_MOCK` 刻意**留在构建期**。机械验证：
容器内 `grep -rl 'NEXT_PUBLIC_USE_MOCK' /app/.next/static` ⇒ **退出码 1（零残留）**
⇒ 该值已被替换成字面量，运行时改不动它。

其余 B6：根 `README.md` 新增「部署」章节（前置条件 / 起停 / 验收出口 / 换地址），**只指一条路径**
（照 `deploy/README.md`），不复制步骤，避免两份文档分叉。
