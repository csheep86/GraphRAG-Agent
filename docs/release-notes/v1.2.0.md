### 6.1 实体抽取质量偏低（真机观察，**不在 S6 修**）

真机图谱出现「本报告汇总了集团」「智能制造与数字服务两大板块合计贡献集团」这类**整句被抽成实体**，数值（`128,560` / `62.3%`）被抽成独立节点，且同一实体**重复 3 份**（6 → 18 个节点）。

答案正确性目前由 **chunk 全文**兜住（引用链路可信、覆盖率 100%），但图谱侧实体质量不达标 → **实体消解归 S9**。

> **归因订正（2026-09-23，Sprint 7.0）**：「整句成实体」**不是 LLM 抽取质量问题**，而是 `_RE_ORG` 贪婪匹配的产物——实测把两条坏样例喂给正则，`_RE_ORG.findall()` 原样返回 `['本报告汇总了集团']` / `['智能制造与数字服务两大板块合计贡献集团']`（`changes/Sprint7.0/integration-log.md` §2 事实②）。
> **Sprint 7.0 已把抽取链路换成真实 LLM**（`extraction_engine=llm`），该现象**已根治**（同一切片对照：mock 档实体样例为「本报告本公司」「2018年12月18日公司」等碎片；llm 档为「招商局公路网络科技控股股份有限公司」「杨旭东」等可读实体）。
> 仍未偿还的部分：实体消解 / 同实体重复（→ **S9**）、`Citation.char_offset`（→ **S10**，llm 档实测模型偏移大多不指向 `mention`，见 7.0 integration-log §5.1）。

### 6.2 `Citation.char_offset` 恒为 0

契约注释：批次 B 为 chunk 起点（0），实体级偏移待 `:Entity` 落 `char_start` 后细化 → **S10**。前端已不依赖它做高亮对齐（见 §6.3）。

### 6.3 `_snippet` 使「摘录长度 ≠ 原文区间长度」

后端 `_snippet` = `text.strip()` 截断 200 字**再加 `…`**（真机 `snippet.length=201`）——strip 造成位移、省略号多算 1 字。实测按契约口径 `char_offset + snippet.length` 切会错位（`highlight_match=False`），前端改为「去省略号 + `indexOf` 对齐」（真机 `index_of_align_hit=True`）。

**建议（不在本版改契约）**：后端改返回 `snippet_start` / `snippet_end`。
