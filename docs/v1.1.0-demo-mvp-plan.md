## 1. 背景与问题定义

### 1.1 v1.0.0 的真实位置

tag `v1.0.0`（Sprint 4 收尾）交付的是 PRD 的**工程外壳**：

- **已达标**：H1 状态机 / H2 大小+MIME / H3 统一错误体 / H4 trace_id / H8 tenacity / H9 Prompt 版本化 / H10 契约先行，CI 4 job 全绿，pytest 110 passed，契约零漂移门禁；
- **未达标**：按 PRD §2 五模块核算整体完成度约 32%——M4（PRD 核心）完成度 0%，M1 解析为空（`storage_key` 恒 NULL），M2 是离线脚本而非服务，M3 无 chunk 级引用（H12/F3 未达标），M5 无审计表；
- **PRD §5 黄金路径 7 步只有 2 步真正通过**（上传返回 task_id + 状态轮询）。

### 1.2 核心诊断：消费端就绪，生产端空缺

| 链路 | 读路径（消费端） | 写路径（生产端） |
|---|---|---|
| 文档 | 列表走前端 Mock | 上传只落元数据，不落盘、不解析 |
| 图谱 | `GraphService` 子图/全局查询真实可用 | 建图靠手工跑 import 脚本，`kg_versions` PG 真源表不存在 |
| 问答 | `AgentService` 真实链路 + 拒答出口 + F3 引用覆盖率校验**已埋且在跑** | 图谱里没有 `chunk-` 前缀证据节点可引用，所以覆盖率恒 0 |

**Sprint 5~8 的本质：把写路径一段段接上，每接一段关一个前端 Mock 开关，直到演示剧本里没有一处假数据。**

### 1.3 v3.0 目标重定位（2026-09-21 裁决）

- **旧口径（v2.3）**：终点是 v1.4.0 的"6 分钟演示剧本 + 零假数据"。

改口径的三条硬理由：

| # | 理由 | 依据 |

## 3. 交付目标与验收口径

### 3.1 演示剧本（5~6 分钟，客户视角）

> **v3.0 口径修正（T13 / §15.1 第 1 行）**：本剧本是**中途演示点**（v1.4.0）的客户视角脚本，**不是 PRD 黄金路径**。两处关键差异：① 剧本上传 2 份年报 PDF，而黄金路径步骤 1 要求**合同 PDF + 3 份 CSV 四源**；② 剧本第 5 步"疑点清单"来自年报图谱，PRD 的疑点来自**四源对齐**。**M4 的完整口径由 Sprint 9 承接**，本剧本降级为"看图 / 问答 / 溯源"子剧本。

1. **上传**：拖入 2 份公司年报 PDF → 秒回 task_id → 页面看状态流转（parsing → extracting → active）；
2. **看图**：图谱页看到实体与关系被画出，kg_version 可见；
3. **提问**：问"甲公司和乙公司存在哪些关联？" → 得到答案；
4. **溯源**：点击答案里的引用标注 → **跳到原文高亮段落**（全场高光，对应 F3/H12）；
5. **疑点**：疑点清单页看到系统自动识别的关联交易疑点，每条带证据链；
6. **审计**：审计页回放刚才全程操作的 trace_id 串联记录。

### 3.2 验收总纲（硬标准）

**A. v1.4.0 中途演示点口径**（原口径，降级保留）：

- PRD §5 黄金路径**步骤 1~6** 走通（步骤 7 = C1~C3 属 Sprint 13，本阶段**不得宣称**）；
- 演示剧本 6 步对应的页面**全部真实数据，无一处 Mock**（settings 页除外，已豁免）；
- 演示数据集上**引用覆盖率 100%**（受控问题集口径，非全量口径）；
- 集成预留位落地且**不影响现有契约**：`npm run gen:api` 无 diff、契约零漂移 CI 绿。

**B. v2.0.0 = PRD MVP 1.0 交付口径**（本计划的最终验收）：

- **模块级**：`specs/m1..m5-*.md` 的验收清单**逐条通过**（不是"演示剧本走通"）；
- **端到端**：PRD §5 黄金路径 **7/7**，且步骤 1 的场景必须是**合同 PDF + 3 份 CSV 四源**（不是 2 份年报 PDF）；
- **准入线**：C1（图谱相对 RAG 增益 ≥10%）+ C2（召回 ≥0.80 / 误报 ≤0.15 / 引用覆盖率 = 100%）+ C3（单位成本落入阈值 + 增量/全量成本比显著 < 1）+ 多跳答对率 ≥0.80 **全部达标**；任一不达标必须按 F1~F5 走**显式降级决议**（落 release notes + 决策记录），**不得静默通过**；
- **硬约束**：PRD §4 的 H1–H12 逐条有判据（优先机械脚本，人工判据须写明验收人）；
- **诚实性**：实验结论必须声明数据来源与外部效度限制（§21.4），**禁止用合成集结论直接宣称真实场景已达标**。

### 3.4 本地部署与离线交付约束

**目标交付形态是企业内网本地部署**（含可能的完全离线环境）。这对本计划（Demo-MVP → PRD MVP 1.0）造成的约束：

1. **外部服务依赖是临时态**：MinerU 云 API / DeepSeek / LangExtract 在 Demo-MVP 阶段接受（否则跑不起来），但**必须收敛到统一 Provider 抽象**，不得散落硬编码——这是 §4.2 批次 A2 进 Sprint 5 的核心理由；
2. **配置层必须有本地/离线开关**：`PRIVATE_DEPLOY_ENABLED`（H6 私域禁外发）在 Demo-MVP 只落**占位**（读取即报"未实现"）——**v3.0 变更：真实实现提前到 Sprint 11**（出网兜底 + 内网双轨，见 §18）；
3. **外部权威数据只能走离线包**：内网无法实时调工商/涉诉 API，所以未来的接入形式是**文件导入**而非 API 调用（见 §8 接缝 8）；
4. **日志与密钥纪律**：延续 `.env` ignore 惯例；本地部署日志留存 ≥6 个月是客户合规要求，本计划只保证 trace_id 贯通（Sprint 8 审计页），日志归档策略留交付阶段；
5. **内网双轨（T18 裁决）**：MVP 1.0 不承诺"已在客户内网跑出性能"，但必须证明**可切换**——`llm_provider` 指向本地 OpenAI 兼容端点（vLLM / Ollama + 开源模型）跑通一次端到端问答，本地解析通路跑通一次 PDF；判定口径与落点见 §18.4。

> **纪律**：只预留，不做集成；只留接缝，不写未来系统的实现。

| **5** | **事件出口接缝** `EventSink` | OA 审批流、BPM、工单/ITSM、企微钉钉通知 | `domain_events` 表 + 进程内分发；事件：`document.parsed` / `kg.updated` / `risk.suspect_created` / `qa.answered`；接口实现只做 `db` + `log` | 1.5 天（S7 批次 D） |

| **7** | **实体映射接缝** `external_refs` | 内部主数据 MDM、HR 组织、工商/股权离线数据、供应商主数据 | `external_refs` 表（`object_type` / `local_id` / `external_system` / `external_id`）——外来实体 ID ↔ 图谱实体 ID 的唯一映射表 | 0.5 天（S7 批次 B） |
| **8** | **外部数据导入接缝** `external_data` | 工商登记、股权结构、涉诉失信、法规/财税库**离线包** | 收口到 `backend/app/services/external_data/`；只定义导入文件 schema（JSON/CSV）+ 手工导入 CLI，**不建表** | 0.5 天（S7 批次 B） |

**合计：7 接缝净增 5.0 天 + 接缝 8 净增 0.5 天 = 5.5 天**（provider 抽象已按"转正顺带"计为 **1 天净增**，不再按 3 天整算）。

> **接缝 2 的口径澄清（T10）**：上表标的 0.5 天在 Sprint 5 批次 A2 只用于 **`documents` 的 8 个可空字段**；`backend/app/services/ingestion/` 与 `IngestionSource` 接口**随 Pro 首个真实数据源落地**，本阶段不建接口——批次 A2 的 2.5 天预算已满（1.0 + 0.5 + 0.5 + 0.5），而提前造一个没有第二实现的接口正是 §8.5 要避免的 stub。`check_seams.py` 据此把该接口登记为**可选**（出现则至多 1 个实现）。
> **接缝 5 的口径澄清**：`db` + `log` 是**两个**本地实现，不是越界；判据是"实现集合 = 登记集合"而不是"数量 = 1"（ADR-0004 §3 第 4 条）。

> **可观测不列入接缝**：它没有"接入方"，本质是配置开关，作为 Sprint 8 批次 E 的实施项（`settings.log_export` 占位）。

### 8.2 `documents` 表预留字段清单（8 个，全部 nullable）

| 字段 | 用途 | 不预留的后果 |
|---|---|---|
| `source_type` | 来源类型（upload/smb/oa/erp） | 未来无法区分数据来源 |
| `source_ref` | 来源系统主键 | 无法回写/回溯 |
| `document_key` | 去重键 | 同一文件重复导入 |
| `content_hash` | 内容哈希 | **无法判定文件是否变化**，增量同步无从下手 |
| `source_version` | 来源侧版本号 | 无法做增量更新 |
| `acl_scope` | 可见范围（来源系统 ACL） | **接入企业系统后无法补，只能重建索引**——这是"权限穿透"的前提 |
| `acl_owner_ref` | 权限主体（对应来源系统） | 同上 |
| `deleted_at` | 软删除 | 来源侧删除无法同步 |

> 复用已有预留：`org_id`（ADR-0003）、`storage_key`、`retry_count`、`trace_id` 已存在，无需新增。

### 8.3 只做三件"便宜事"（防止预留变成过度设计）

1. **字段预留**（最便宜）：新表建表时带齐可空字段，零额外成本；
2. **接口收口**（中等）：可变点收进 `app/services/{auth,ingestion,export}/` 或 `app/adapters/`，主链路只依赖接口，**不写未来实现**；
3. **事件出口**（中等）：关键节点发一个领域事件，未来接 OA/工单只需订阅。

### 8.4 硬规则：预留字段**不进 API 契约**

`contracts/openapi.yaml` 是 CI 门禁（契约零漂移 + `npm run gen:api` 生成前端类型）。预留字段一旦进契约：

- 契约膨胀 → 前端类型膨胀 → 每次 `gen:api` 都有 diff；
- 更糟：**进契约即对外承诺**，改它又要走契约流程。

> **规则**：预留字段一律 nullable 且**不进 API 契约**；只有真正启用某个集成时，才把对应字段提升到契约。
> **已写入根 `CODEBUDDY.md` §功能预留原则（第 4~6 条）**，于 Sprint 5 动工前生效（不等 Sprint 8 治理批次）；第 6 条（实现集合 / 配置消费者）由 `check_seams.py` 机械校验。
> 判定口径：`uv run python scripts/export_openapi.py --check` 无 diff。

### 8.5 三个明确不做

| 不做 | 理由 |
|---|---|
| 动态插件加载（`entry_points` / `importlib` 扫描） | 调试成本与安全审计成本远超收益；本地部署客户不会自己写插件 |
| 通用连接器框架 / 迷你 ETL | 通用抽象一旦做错，未来每个连接器都要跟着改；**按需做具体连接器**才对 |
| 为未来系统写空实现 stub | 死代码 + 假安全感，还会让真实接口形状被"猜错的 stub"带偏 |

### 8.6 接入能力的三条隐性瓶颈（设计时就要知道）

1. **权限穿透**：用户问的问题，答案可能跨权限边界。必须在**检索层**过滤，而非展示层——所以 §8.2 的 `acl_scope` 是硬前提；
2. **实体消解压力随接入系统数增长**：每接一个系统就多一套实体 ID 体系；`external_refs`（接缝 7）是接入数量的瓶颈，E1/E2 数据债会随之放大；
3. **时效性与版本**：企业数据持续变化，用户会问"当前状态"；需 `content_hash`/`source_version`（§8.2）与未来图谱边的 `valid_from`/`valid_to`（本计划不做，登记 v1.5+）。

## 9. 企业内系统集成全景

### 9.1 六个流向

```
输入侧 ──► [带知识图谱的企业问答系统] ──► 输出侧
身份域    知识来源域    基准数据域    算力模型域  │  消费域    动作域
AD/LDAP   共享盘/OA    工商股权     内网 LLM     │  BI/底稿   OA 审批
企微钉钉  网盘/ERP     内部主数据    GPU/OCR      │  门户      工单/通知
HR 组织   CLM/CRM     MDM                        │  Office    待办
                    支撑侧：运维合规域（日志/监控/4A/DLP）+ 基础设施域（网关/MQ/对象存储）
```

### 9.2 按必要性分级（= 未来接入顺序）

| 级别 | 系统类别 | 不接的后果 | 归属版本 |
|---|---|---|---|
| **P0 准入** | 统一身份认证、内网 LLM、网络与域名、日志留存 ≥6 个月 | **进不了门**，客户 IT 直接否决 | Pro |
| **P1 数据入口** | 共享盘/网盘、OA 文档库、HR 组织架构同步 | 只能手工上传，没数据 | Pro |
| **P2 价值放大** | 工商/股权离线包（经接缝 8 导入）、ERP/财务、内部主数据 MDM | 效果打折，M4 准确率上不去 | Enterprise |
| **P3 闭环** | OA/BPM、工单/ITSM、消息通知 | 结果进不了客户工作流，沦为"玩具" | Enterprise |
| **P4 合规运维** | 监控、统一日志平台、堡垒机、备份容灾 | 上线评审过不了 | 交付阶段 |

### 9.3 三种同步模式（比"接哪些系统"更重要）

| 模式 | 适用系统 | 更新机制 | 难度 |
|---|---|---|---|
| **拉取式（批同步）** | 共享盘、网盘、文档库 | 定时扫描增量（`sync_cursor` 水位 + `content_hash`） | 低 |
| **推送式（事件驱动）** | OA、ERP、CLM | Webhook / MQ 订阅 / CDC | 中 |
| **联邦式（实时查询）** | 强时效数据（在途、库存、当前状态） | 问答时实时查、不落图 | **高，建议长期不做** |

### 21.4 诚实性约束（强制）

1. 结论**必须标注数据来源为合成集**，并声明外部效度限制（合成分布 ≠ 真实合同 / 发票分布）；
2. 同时报告**演示集（真实文档）**的召回 / 误报作为交叉参考，即便其规模不达准入线；
3. **禁止**以合成集结论对外宣称"真实场景已达标"；对外陈述统一为"在合成基准集上达到 X"；
4. 若某指标仅在合成集达标、真实集明显偏低，**必须在报告首页并列展示两个数字**。
