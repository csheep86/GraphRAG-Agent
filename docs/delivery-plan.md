## 1. 重排原则（**按需求，不按旧编号**）

1. **签单优先**：能解锁签单的排最前（A 组交付骨架 + SSO）。
2. **基础设施不晚于功能**：PG 切换**尽早**——每多一天 SQLite 开发，就多累积一批方言债（`Uuid` 无连字符格式已踩过一次）。
3. **依赖驱动**：有前置关系的严格串行；无依赖的并行。
4. **每条需求配护栏**：阶段出口 = 该阶段的护栏**在 CI 上绿**。缺护栏的需求**不宣称完成**。
5. **不单独为"转 PG"开阶段**：它是 P1 的一部分，随 G-8 落地。

## 4. P1 内部顺序（**最高优先级，解锁签单**）

P1 两条线**可并行**；A 组内部有严格先后：

| 序 | 项 | 为什么这个顺序 |
|---|---|---|
| **1** | **DR-A6**：compose `build:` → `image:` + tag 规范 | **性价比全场最高**（几行 yaml），且是补丁流程的唯一前提。**先做它，签单路径立刻解锁一半** |
| **2** | **DR-B1**：compose 加 PG 服务 + `DATABASE_URL` 改 PG | 基础设施；越早切，方言债越少 |
| **3** | **DR-B2 / G-8**：CI 起 PG，pytest 跑在 PG 上 | **不落地 ⇒ B 组断言全是假的** |
| **4** | **DR-B3**：清理 SQLite 兜底分支 | 随 B1/B2 一并做 |
| **5** | **DR-A2**：`plugin.yaml` 最小字段集 | 插件规范的骨架 |
| **6** | **DR-A1**：`deploy/variants/<客户>.yaml` | 依赖 A2 的字段定义 |
| **7** | **DR-A3**：构建期烘焙（Dockerfile COPY 插件） | 依赖 A1/A2 |
| **8** | **G-11**：接缝签名快照 | 兑现"V2.0 才需重做插件"的商业承诺，纯脚本、成本极低 |
| **9** | **G-14**：基座契约纯净性断言 | 随首个插件并入时启用 |
