## 1. 背景与问题

| 叙事层 | 缺「资产视角」：没有业务域概念，首页只有 4 张指标卡 + 两条列表，看不出「有多少块知识、各自什么状态」 | `frontend/src/lib/nav.ts`（仅 2 组 7 项）、`frontend/src/app/page.tsx` |

## 2. 目标 / 非目标

**目标**

1. 首页具备「资产视角」：业务域一等公民、状态可见、可点击进入
2. 业务域可**后台配置增减**，前端菜单随之变化（可演示的抓手）
3. 图谱具备时间语义：至少能声明「该事实截至何日成立」，并能区分当前/已失效事实
4. 清掉演示暴露的 UI 缺陷

#### P3.0 一句话结论（为什么是自研）

双轨对照实验（同一语料 / 同一判分 / 重复 3 轮）：

| 指标 | 自研 | Graphiti |
|---|---|---|
| 时态字段抽取 | ✅ `valid_from` 覆盖 **100%** | ✅ 双时态齐全 |
| **过期治理（旧事实自动失效）** | ✅ **3/3**（确定性规则） | ❌ **1/3** → 换真实中文语义向量后 **0/3** |
| 当前值 / as-of 回溯 | ✅ 3/3 · 3/3 | — |
| LLM 调用 | **2 次** | 多次（抽取 + 去重 + 矛盾判定） |
| 新增依赖 | **0** | graphiti-core + Embedding + cross-encoder |

**根因**：本项目有**受控 schema**（`relation_type` 枚举），同 `(head, relation_type)` 出现不同 `tail`
即结构性矛盾，精确匹配可判定；Graphiti 是**开放抽取**，要靠语义相似度 + LLM 比较自由文本，
实测会把「变更陈述句」错杀、而让真正过期的旧边活着。

#### P3.2 仲裁规则（确定性，不依赖 LLM、不需要 Embedding）

> 完整表述与"为什么"见 **ADR-0005 §5**。此处为执行时可直接照抄的口径。

| # | 规则 | 触发 | 动作 |
|---|---|---|---|
| **R1** | 跨文档 | 同 `(head, relation_type)` 新事实，`valid_from` **严格晚于**旧边 | 旧边 `valid_to := 新边.valid_from`、`expired_at := 写入时刻` |
| **R2** | 同文档变更句 | 同 `(head, relation_type)` 多条边 `valid_from` **相同**（「由张三变更为李四」会同时抽出旧值与新值） | 保留 `tail` 在原文中**最晚出现**的那条；其余 `valid_to := valid_from` |
| **R3** | 禁止同批次互封 | 失效动作**不得**作用于同批次（同一文档）内刚写入的边 | 与 R1 的"严格晚于"共同防过度失效 |
| **R4** | 不猜值 | 文本无显式日期 | `valid_from` 取 `document_date`；`valid_to` 留 **NULL**，禁止推断区间 |

> ⚠️ **R3 是实测踩出来的**：首版用 `<=` 且不排除同批次，结果「变更句」先写出的新值边
> 被后写出的旧值边**反过来封掉**，当前值全线阵亡（详见 `temporal_poc/README.md` §4 坑 5）。
> **照抄规则时不要"顺手优化"掉 R3。**

#### P3.3 数据模型（四字段双时态）

| 字段 | 维度 | 含义 | 空值语义 |
|---|---|---|---|
| `valid_from` | **事实维** | 事实开始成立的日期 | 不可空；无显式日期取 `document_date` |
| `valid_to` | **事实维** | 事实失效日期 | **NULL = 仍有效** |
| `created_at` | **摄入维** | 本条边写入图谱的时间 | 不可空 |
| `expired_at` | **摄入维** | 本条边被取代的时间 | NULL = 仍是当前边 |
| `source_document_id` | 血缘 | 事实来源文档 | 不可空 |

**两套维度必须分开**：事实维回答"现实中从何时到何时成立"（来自文档）；
摄入维回答"我们何时知道、何时被推翻"（来自系统）。只做一套 = 半时态。

**与 `kg_version` 正交**：`kg_version` 是**图谱快照**的构建批次（可回滚），
四字段是**单条事实**的成立区间（可回溯）。二者**不得互相替代**。
