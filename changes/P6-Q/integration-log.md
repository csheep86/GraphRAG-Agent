## 4. 根因：`build_chat_model()` **没有钉 temperature**

```python
# backend/app/services/providers/llm.py
return ChatOpenAI(
    model=settings.llm_model,
    api_key=settings.llm_api_key,
    base_url=settings.llm_base_url,
    timeout=settings.llm_request_timeout_seconds,
    max_retries=0,
)   # ← 没有 temperature ⇒ 走厂商默认采样
```

- 上层拒答的唯一理由分支是 `no_grounded_evidence`（`agents.py:499~507`）：
  LLM 本轮没交出 `chunk-` 前缀的 evidence ⇒ **按 M3 验收 3 拒答**；
- 后端日志里 **0 条** `agent_citation_ungrounded_dropped` ⇒ **不是归因闸门把引用丢光了**，
  是模型那一次压根没给（或给的格式不可回查）；
- 这与「同一个 prompt / 同一份注入，换一次调用结果就不同」的现象一致 ⇒ **采样抖动**。

**这一条也是"它确属误伤"的证据**：检索层把答案摆在桶内第 1 名，隔离重测 17/17 答对
⇒ 模型**答得出来**，却在那一次拒了 ⇒ **真真切切的误伤，只是时有时无**。

## 5. 为什么不顺手把 `temperature=0` 提交上去

对照实验已经做了、数据也拿到了（§3 第 3~5 趟），**实验用的那一行已经还原**（`git diff` 下 `app/` 零改动）。
但把它作为**正式改动**提交，有三件本批无权替用户拍板的事：

1. **它是全局采样开关，不止问答在用** —— `build_chat_model()` 是 ADR-0004 §2.1 的**接缝 3**，
   同时被 **`langextract`（抽取）/ `ontology`（本体建议）/ `agents`（问答）** 三条路径调用
   ⇒ 改它等于同时改入图产物，可能影响 C2-a / C2-b 已落的 gold 命中，以及 C1 与历史判分表的可比性；
2. **与历史数字的可比性** —— C1 虽已被 P6-J 降级，但既有 40×2 判分表是在"未钉温度"前提下判的；
   换了采样 ⇒ 那批分数**不再同源**（P5-B 记过同一个坑：0.0294 与 0.1765 不可直接比）；
3. **"为了让它绿"是 A6 明令警惕的动机** —— 钉 `temperature=0` **不是**放宽拒答判定（判定一行未改），
   但它确实是为了让这条判据读数归零 ⇒ 这类改动**应由用户裁决**，不由执行批顺手落地。

⇒ 按 repo 纪律（先缩范围，后报告）：① 它不在任一 Non-goal 里；② **可以整体推到下一批并登记**
（实验数据现成，下一批只差拍板）；③ 因此**报告但不动手**。

候选三条（留给下一批挑）：

| 方案 | 一句话 | 代价 |
|---|---|---|
| **O1 钉 `temperature=0`** | 三趟 T=0 全部读 0；六趟样本下的首选 | 改接缝 3 ⇒ 影响抽取 / 本体路径；同时要决定是否做成 `settings.llm_temperature`（做成字段会触发 `.env.example` 同步 + "有消费者"证明） |
| **O2 只钉问答侧** | 只给 `agents._ensure_chat` 加 temperature，抽取不动 | 两侧同源会漂 ⇒ 要有测试钉住"差异是有意的" |
| **O3 不钉，把抖动写进判据口径** | 判据改为「多趟取最大」或报告同时出点估计 + 抖动区间 | 最诚实，但判据不再是单次可判定 ⇒ 演练成本上升 |

## 7. 收尾三问（自答）

1. **有没有"顺便做的"？** 没有。文档改了三处，全部对应 `proposal.md` §T5 与 §8 判据 8 的既定任务；
   `temperature=0` 那一行算"多做的"，但它**只存在于实验期间**、已还原，
   且它的唯一产出是 §5 那张候选表——那是决策材料，不是功能。
2. **有没有为躲坑而绕路的实现？** 有一处要坦白：**我把"多趟复跑"当成了取证成本，不是省事的捷径**——
   单趟 `--live` 已经与 A6 的旧读数不一致（FAIL→PASS 的混合信号），本可以只跑一趟就写
   「现在读数是 0」，但我选了重复跑：**因为"这次绿不等于下次绿"本身就是最重要的事实**，
   躲着它会让整批结论失真。代价是多花了 200 多次调用（见 D7），这笔账算在本批头上，没有偷偷摊销。
3. **验收是真跑还是读代码？** 全部实跑：探针两次、live 六趟、Q28 隔离 17 次；
   各种门禁（ruff / pytest / seams / openapi / readiness / drift）以**脚本输出**为准；
   **CI 尚未出结果 ⇒ 本批结论在 CI 绿之前不作数（R-10）**。
