# 13 · as-of 视图的证据位次（ADR-0005 §5 R5）

2026-09-30，用户裁决采纳。

## 起因

Sprint 10.5 的双时点演示里，`as_of='2025-06-01'` 的主链落在「加班与调休管理办法」
——一份 **2026 版**文档、最后一跳没有日期。两个候选原因必须分开，修法完全不同：

1. 候选里根本没有当日成立的带日期链（召回问题）；
2. 候选里有，但输在 sort key 某一维（排序问题）。

## 诊断（`probe_as_of_ranking.py`）

12 条候选的**前四维全部相同**：

```
prio=0  rank=8  hops=3  verdict=unknown        ← 12 条全都一样
跳数终点名一致名叫 POLICY_CLAUSE
```

⇒ 胜出者由第 5 维 `tuple(ids)` **字典序**决定，答案事实上随机。
带日期的链路排在第 2 / 7 / 10 位（员工考勤管理制度（2025 版）/ 月度补卡次数 / 本规定）。

**结论**：这不是优化题，是口径空缺——没有一位来裁决打平的候选。

## 判据（落 ADR-0005 §5 R5 + specs/m2 §4.6.5）

```
as_of 非 NULL ⇒
    0  最后一跳被该时点证实：valid_from <= as_of 且 (valid_to IS NULL 或 valid_to > as_of)
    1  其余（无日期 / 尚未施行 / 已失效）⇒ 让位，**不剔除**
as_of 为 NULL ⇒ 恒 0 ⇒ 缺省零变化
```

插入位置：`_TEMPORAL_RANK` 之后、`tuple(ids)` 之前 ⇒ 只为打平的候选裁决，
不许为了时点证据挑一条更长或解释力更弱的链。

## 本次踩到的坑：**探针比产品更容易出错**

第一版 `probe_current_view_composition.py` 裸查全图、**没带 `_temporal_view` 谓词**，
据此报出「缺省视图里仍有 37 条已失效末端」，并据此提出了议题 1（以为缺省不剔除失效）。
实测加回谓词后：缺省视图 939 条链末端 `valid_to` **全部为空** ⇒ 缺省本来就正确，
议题 1 不成立，撤回。

教训写进探针文件头了：**任何"候选构成"类探针必须复用生产谓词本身**，
自己重写一遍过滤条件，等价于重犯「同一判断散写成多份」的老错。第二版又因为
把"缺省与显式今天的链总数不等"当成漂移（其实 939 > 99 是 `graphs.py:239`
明写的有意设计：缺省不限制 `valid_from`），再一次误报。
