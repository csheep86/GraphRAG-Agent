> 11 号定的是「派生边继承**条款自身**的窗口」，本文档定的是「条款自身**没有**窗口时怎么办」。

## 1. 要解决的问题（实测数据均为 2026-09-30 真机）

L2-③（as-of 双时点问答）的检索层**已经实现且实测生效**：同一句问话在两个时点的候选集完全不同——

| as_of | 候选行数 | 末端条款 |
|---|---|---|
| `null`（当前） | **165** | 全部 2026 版（`2026-01-01~∞`） |
| `2025-06-01` | **25** | **全部 2025 版**（`2025-01-01~2025-12-31`） |

2026 版条款在 2025 视图里一条不剩 ⇒ **过滤是对的**。但两个时点选出来给前端的
**是同一条链**：

```
李静 -[HAS_POSITION <none>~<none>]-> 产线操作工
    -[APPLIES_WORK_TIME <none>~<none>]-> 综合计算工时制
    -[GOVERNED_BY <none>~<none>]-> 工时制实施细则      ← 三跳全部无日期
```

无日期 ⇒ 不被任何日期证伪 ⇒ 在任何时点都成立 ⇒ 永远赢。**差异存在，但被这条
"横穿所有时代"的链挡住了。**

根因（`probe_document_scope.py` 实测）：

```
自身无邻接窗口的 POLICY_CLAUSE：66 条（占 32%，与 11 号记录 §4 的 44 条同族、
因语料扩量而增长）
其中能在图里挂到文档级实体的：3 / 66 条
节点属性全集：canonical_name / char_end / char_start / confidence /
             entity_type / id / kg_version / mention / org_id / trace_id
```

**关键结论**：节点属性里**没有任何 doc_id / source / chunk 线索**，图里也不存在
「条款 → 所属文档」这条链接 ⇒ **文档级作用域无法在图侧回填**，只能在**入库那一刻**
（脚本明知每个实体出自哪个文件）建立。

## 2. 提案规则（R4-b，一句话）

> **条款自身一个候选窗口都没有时，其窗口 := 它所属文档**自称条款**显式声明的窗口。**

展开成四条，每条都是硬边界：

1. **只在自身无窗口时填补**，已有窗口**绝不覆盖**（11 号记录的派生边继续按自身窗口走）；
2. **文档窗口的定义**：该文档中自称条款（含 `本规定` / `本制度` / `本办法` / `本细则`
   之一的行）里显式写出的
   - 施行日 → 复用现有 `app.services.parsing.document_date.resolve_document_date`
     （已经过 `probe_document_date.py` 六份语料验收）；
   - 有效期至 → 新增**同构**解析器（`12` 号伴随代码），只认 `有效期至 <日期>` 句式；
   - **读不出就 NULL**，不补值；
3. **歧义 ⇒ 留空**：同一个条款实体出现在多个窗口不同的文档中 ⇒ 与 11 号「恰好 1 个
   候选才继承」同一套纪律，一律留 `None`；
4. **值必须逐字可回查**：继承的每个字符都来自该文档正文那一行，不存在"推测出来的日期"。

### 反面枪口（明确禁止）

| 做法 | 为什么禁止 |
|---|---|
| 凭文件名 `attendance-policy-2025.md` 里的 `2025` 推定有效期 | 文件名不是文本证据；且 M5 §4.5 只落 `filename_hash`，**没有文件名可依据** |
| 把文档日期既当 `valid_from` 又当 `valid_to` | 会写出单点窗口，语义是"当天有效"，凭空制造失效 |
| 自身有窗口的条款改用文档窗口 | 覆盖＝丢掉更细的证据，且会让「2026 版正文里引用旧版条款」的那类交叉引用被错标 |

## 3. 为什么这不违反 R4（这是本记录最要紧的一节）

ADR-0005 §5 R4 / `specs/m2` §4.6.2 R4 原文：

> 文本未显式给出起止日期时，`valid_from` **取 `document_date`**，`valid_to`
> **留 NULL**——**不得**由模型或代码推断区间。

**注意 R4 本身就已经允许了 `valid_from := document_date`** —— 本记录在 `valid_from`
侧**没有做任何新主张**，只是把它落到实处（此前没人写这条写入路径，见
`document_date.py` 模块 docstring 第 4-8 行：「已落地，但**没有任何写入路径**」）。

真正的新主张只有 **`valid_to` 一侧**，且被收到最窄：

- **允许**：文档正文**逐字写出**了有效期终点（`有效期至 2025 年 12 月 31 日`）⇒ 取该值为 `valid_to`；
- **禁止**：文档没写 ⇒ `valid_to` 仍为 `NULL`，**不推断**、不套"当年最后一天"、不按文件名补。

之所以必须允许这一侧，是因为**不做比做错更危险**：2025 版语料若在 `valid_to` 上留
`NULL`，语义是「2025 版仍有效」，as-of 双时点会变成「两个时点都回答 2026 版」——与现状
（两个时点都回答同一条无日期的链）**同样的假**，但看起来更像真的，更难发现。

⇒ 因此这是 **R4 措辞边界的增补（R4-b）**，不是放松 R4；即便如此，仍需正式写进
`ADR-0005 §5` 与 `specs/m2 §4.6.2`，不许只活在代码注释里。

### 残留问题（不掩盖）

主链还剩 26 条无日期边，其中 **25 条是 RULE 边**（我们自己生成的，不是模型抽不出）。
成因查清了：

```
图上 POLICY_CLAUSE 共 158 个
登记册               113 条
⇒ 多出的 45 个是"无当前出处"的陈旧实体
```

它们是早几轮语料修订留下的 span 节点——管道只 MERGE 不删除，语句改过一轮后老节点
还在，而**当前没有任何文档产出它们** ⇒ 文档中根本无处可查它们出自哪一份 ⇒ 登记不上。
**这不是口径缺陷，是图的清洁度问题**；清理需 `--purge` 整版重建（会把 `ent_*` 抽
取产物连带删掉 ⇒ 要重跑 MinerU + LLM，花钱且有抖动）⇒ ~~是否清理由你裁决，我没做~~

> ✅ **2026-10-09 已裁决（用户采纳）：不清理，登记为「已知不修」**。理由：成本是确定的
> （重跑 MinerU + LLM，且有抽取抖动），收益只有清洁度 —— 与 P5-B §6 环境债台账的
> 「⑥ 已知不修」同类。**触发复议的条件**：出现真实大语料的问答需求，或 `--purge` 因别的原因
> （如换语料 / 换 kg_version）本来就要跑 ⇒ 那时顺带清理，不单独为它开一批。
> ⚠️ 上一句「是否清理由你裁决」**已过期，勿再当作未决项**。

**必须连同出现的坏消息**：虽然两个时点的路径不同了，但 2025 时点的落点
`加班与调休管理办法` 本身是**一份 2026 版制度**（它那一跳无日期，故任何时点可达）。
也就是"2025 年问话 ⇒ 指向一部尚未出台的办法"。这正是三值语义下「无日期跳照旧保留」
的自然后果，不是新引入的错误，但**演示前必须知道它**。

## 6. 不做的事

- **不重抽**：态势所需的日期都是**确定性**从正文读出来的，不需要 LLM；重抽会把已验收
  的 60 条 `valid_to` 重新暴露给模型抖动。
- **不碰 evidence chunk 的时态**：即便本口径落地，`POST /agent/query` 的**答案措辞**
  仍不区分时点（证据片段本身没有分代）⇒ 那是下一个断点，**不计入本记录的成功范围**。
- **不改 §6 的两条已知脏数据**：交叉引用污染，维持 11 号记录的「登记不改写」裁决。
