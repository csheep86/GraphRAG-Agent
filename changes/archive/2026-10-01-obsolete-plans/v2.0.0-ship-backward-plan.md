## 4. 关键路径与最长链

```
上线 Gate G1~G5
   ▲
   │  G3（C1~C3）是唯一需要"实测数字"的 Gate —— 只能最后由 S13 交
   │
 S13 ──需要──► S12-D 成本仪表盘（C3 度量载体）
   │              ▲
   │              │ 需要"增量 vs 全量成本比"→ 需要增量重算可测
   │              │
   │           S12（M6 完整版）
   │              ▲
   │              │ 需要 entity_merge_candidates（校正 GUI 绑定）
   │              │
   └──────────► S9（M4 完整化）──需要──► S7（1 类算法）──需要──► S5（建图）
```

**最长链（关键路径）**：`S5 建图 → S9 四源 + 实体消解 → S12 M6（含成本仪表盘）→ S13 C1~C3 实验`。

**并行支线**（不占关键路径，但 Gate 需要）：
- `S5-A2 接缝 → S11 接缝收口 + RLS + 双轨`（G4 H6/H7 依赖）；
- `S10 多跳 + :Chunk 证据 → S13 多跳答对率与引用覆盖率`（G3 依赖）；
- `S12 期间并行：数据集生成器 + 纯 RAG 基线`（§21.1/21.2）——✅ **已决议并行启动**（**O-5**，见 §7）。

> **排计划的直接含义**：**S5 和 S9 是两处"一堵就全堵"的节点**（S5-A2 接缝是 S11 的前置；S9 的实体消解是 S12 的前置）。**压缩工时应优先看这两处，而不是 S13。**

## 6. SDD 每批次产出物与落点（**已决议 2026-09-21**）

### 6.1 决议（替换原 O-1 待裁决项）

**方案 A′ —— 落点复用既有 `changes/Sprint<N>.<M>/`，SDD 三件套与联调证据同目录并存。**

**依据（已核实项目实际，非推断）**：

| 事实 | 证据 |
|---|---|
| `changes/<Sprint>/` **已是项目事实约定** | `changes/archive/` 下有 6 个批次目录：`2026-09-20-Sprint4.10.1` / `…10.1.5` / `…10.1.6` / `…10.2` / `…10.3` / `…10.4` |
| 既有批次产出的**是证据链，不是三件套** | 每个目录含 `integration-log.md`（+ `probe_*.py` + `probe-output.log`）；**三件套从未被使用过** |
| OpenSpec 工具链**确未启用** | `openspec/specs/` 与 `openspec/changes/archive/` **均为空**；README 行 25 已改口径 |

**结论**：**不新开路径、不启用 OpenSpec CLI**——只在既有批次目录内**补上事前计划的三件套**。零迁移成本，且与历史证据链走同一归档通道（`changes/archive/<日期>-Sprint<N>.<M>/`）。

### 6.2 每个批次（`changes/Sprint<N>.<M>/`）的固定产出

| 文件 | 性质 | 必填 | 说明 |
|---|---|---|---|
| `proposal.md` | **事前**：为什么做 / 改什么 / 影响面（契约·前端·后端·Prompt）/ 不做什么 | **是** | 模板 `specs/_template/proposal.md` |
