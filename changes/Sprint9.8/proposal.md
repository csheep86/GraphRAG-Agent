# Sprint 9.8 —— 前端观感对齐（基准 `docs/demo.html`）

> 登记日期：2026-09-29。**临时插入批次**（与 9.5 / 9.6 同，不计入 plan §13 的
> S5~S13 序列）。用户决议：**排在 S10 之前**，先定型观感与交互，再让
> S10（证据链 / 多跳展示）与 S12（校正 GUI / 成本仪表盘）按它落功能。

## 1. 为什么做

用户原话痛点：「现在的 UI 全黑乎乎的，我的 demo 右侧是白的，从用户角度出
发才有比较好的感受」。

根因已核，非猜测：

| 事实 | 位置 |
|---|---|
| `--background: #0b0b0f`（近黑），`body` 直接吃该变量 | `globals.css:19` + `:122-128` |
| **侧栏与内容区共用同一变量** ⇒ 一起黑 | `sidebar.tsx:84` 的 `bg-background` |
| 全站无主题切换（`@custom-variant dark` 已声明，但无 `darkMode` / `next-themes`） | — |

而 `docs/demo.html` 的形态是**侧栏深色渐变 + 内容区浅色**（两者**解耦**）。
⇒ 本批次本质不是"换个配色"，是**把侧栏与内容区拆成两套底色**。

**这不是新想法**：`frontend/src/lib/nav.ts:54` 早已写明「对齐
`docs/demo.html:409-416` 的 7 个业务域」——DOMAIN 组 7 域即照它建的。
本批次把该基准从**导航**扩展到**观感 + 页面骨架**。

## 2. 改什么

| 批次 | 内容 |
|---|---|
| **P0** | 主题反转：侧栏深色 + 内容区浅色（**最先做**，预计一天内） |
| P1 | 勘察：视觉差异比对表 + 现有页面清单 + 缺的视图 |
| P2 | 视觉底座：侧栏渐变 / `page-head` / `kpi-row` / 卡片网格组件化 |
| P3 | 首页总览改成 demo home 形态（**数字必须真**） |
| P4 | 数据源接入 / 权限与角色（契约大概率无端点 ⇒ **先裁决** placeholder 或不做） |
| P5 | 收尾门禁：tsc / lint / **契约零漂移** / 浏览器点验截图对照 |

## 3. 影响面

| 面 | 影响 |
|---|---|
| **契约** | **无**（P5 有零漂移校验：本批次不得产生 `openapi.yaml` 变更） |
| **前端** | **全部**（配色变量、侧栏、各页面观感） |
| **后端** | **无**（不新增 / 不改动任何接口） |
| **Prompt** | **无** |

⇒ 与 Sprint 9 批次 C（`backend/` + `contracts/` + 迁移）**目录零冲突**，
两者可并行；串行时**先做本批次**（底座先行，反序要重做页面）。

## 4. 明确不做

- **不动契约、不新增后端接口**（纯前端批次）
- **不接假数据**——见下条红线
- **不放开** 6 个业务域的 `disabled` + 「规划中」状态（A16 诚实可核：
  给可点路由等于宣称已交付）
- 不做业务域内新功能（属各自 Sprint）

## 5. 红线：demo.html 里的数字是编的

demo 是**视觉原型**，其 KPI 为示意值（首页 `48,620` 实体 / `216,340` 边 /
`1,284` 查询 / `23` 预警；数据源页 `5` 个已接入系统等）。

`plan §7.2` 硬门槛是「演示剧本 6 步**零假数据**」，决策 **A16** 要求
「**诚实可核**」。⇒ **照抄示意值即视为造假**：每个数字必须能追到真实接口，
取不到显示 `—` 或「未接入」，**不得**为凑数字新增假接口。
**本条优先于"看起来像 demo"。**
