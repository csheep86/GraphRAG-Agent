# P7-S：修 `_build_citations` 去重 + 给问答链路加「注入证据」可观测出口

> 承接 **P7-R §7.1 线 B**。用户 **2026-10-14 授权改产品主链路**。
> 为什么**不**并入 P7-R：P7-R 的 Non-goals 明写"不改产品主链路"，
> 混着做会把「测量」与「改产品」两件事的边界糊掉 —— 那正是 P7-K 一路在躲的坑。

---

## 1. 起点坐标（全部来自 P7-R 已落盘的证据，不是猜的）

| # | 事实 | 出处 |
|---|---|---|
| 1 | `_build_citations`（`app/services/agents.py:976-987`）**完全不去重**，只按 LLM 给的 `evidence` 顺序逐条回查 `append` | P7-R §6.2 表 #1 |
| 2 | 实测同一 chunk 在 citations 里出现 **3 次**（`chunk-0c7b712dc257` ×3） | P7-R §5.3 |
| 3 | citations 顺序 = 模型 `evidence` 顺序，**无稳定排序** | P7-R §6.2 表 #2 |
| 4 | **判不开"chunk 选择漂 vs LLM 措辞漂"**：注入 prompt 的 chunk_id 序列**没有出口** | P7-R §6.1 / §6.5 |
| 5 | 内部复现检索路径**失败**（`fetch_evidence_chunks` 直调返回 0）⇒ 只能从产品内部加出口 | P7-R §6.4 |
| 6 | 并发已**排除**（全链路只有一个 `await`，无 gather / 线程池） | P7-R §6.2 表 #6 |

⇒ **#1 是确证缺陷，与任何定性无关**：无论漂移最终归因到哪一侧，
citations 里出现重复 chunk 都是错的。

---

## 2. 做什么

1. **修去重**：`_build_citations` 按 `chunk_id` **保序去重**。
   同一 id 带不同 span 时（`#提及` 后缀会产生不同 span）⇒
   **保留区间最精确的那条**，不是简单丢弃第一条。
2. **加观测出口**：把**注入 prompt 的 chunk_id 序列**变成可观测、可复跑的读数。
3. **反向验证 + 单测**：拆掉去重 ⇒ 测试**必须红**（纪律 R-9：恒绿即失效）。
4. **用观测出口重跑判别实验** ⇒ 给出「检索漂 / 生成漂 / 两者都漂」的**三选一结论 + 读数**。

---

## 3. Non-goals（本批**不做**的事）

1. **不改 rubric-v2**（判分口径的升降属 P7-R §7.3 的岔路，等本批证据出来再裁）。
2. **不改判分口径** —— 本批只负责把证据摆上桌。
3. **不修检索排序**（除非观测证据明确指向它；届时停下报告，不自行扩大范围）。
4. **不动** `_to_citation` / `_resolve_citation_span`（偏移换算是确定性的，与本现象无关）。
5. **不把"答案逐字一致"当本批成功标准** —— 本批的成功标准是**拿到判别结论**，
   结论可以是"不可达"。

---

## 4. 出口判据

| # | 判据 |
|---|---|
| 1 | 去重有单测，**且反向验证通过**（拆掉 ⇒ 必须红） |
| 2 | 观测出口可用：**一条命令**能拿到注入的 chunk_id 序列，且结果可复跑 |
| 3 | 用观测出口跑出判别结论：**检索漂 / 生成漂 / 两者都漂** 三选一，**附读数** |
| 4 | 修完后**实测**验证：重复 chunk 现象消失 |
| 5 | pytest 不降、三件套（ruff / format / 接缝）干净、CI 四 job 全绿 |

## 5. 升级情况（出现即**停下报告**）

| # | 情况 |
|---|---|
| 1 | 加观测出口若需改 `AgentQueryResponse` schema ⇒ 影响契约 / 前端，**停下** |
| 2 | 观测证据指向**检索排序**缺陷 ⇒ 停下报告（可能撞 P6-V5 或检索口径裁决） |
| 3 | 发现**注入 prompt 的 chunk 序列本身每次不同** ⇒ 停下报告
      （这比措辞漂移严重：意味着证据基线不固定，C1 的"重判差异题"连基准都没有） |
| 4 | 去重改动导致既有用例红 ⇒ 先判断是"用例在保护错误行为"还是"改错了"，
      **不许直接放宽用例**把红洗绿 |
