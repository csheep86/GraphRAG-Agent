## 1. 真机勘察：多跳**不是**从零做，而是**只在考勤域成立**

读代码 + 真机对照的结论（与 plan §17.1「代码中无变长 Cypher，仅 1–2 跳定长模式」**已不符**——那是 2026-09-24 的口径）：

| 事实 | 出处 |
|---|---|
| 多跳 Cypher 是 `-[:RELATION*1..3]-`，`_MAX_HOPS = 3`，与 PRD「3 跳内」一致 | `reasoning.py:48,135`（Sprint 9.5 批次 D1，2026-09-28 真机调优过排序） |
| 已接进响应：`agents.py:396` → `AgentQueryResponse.reasoning_path`（契约已有 `ReasoningPathHop`） | `openapi.yaml:2242` |

但真机一查域分布，缺口就露出来了（`probe_b0_multihop_scope.py`）：

| kg_version | 实体 | 是否命中多跳终点白名单 | 多跳 |
|---|---|---|---|
| `attendance-demo-v1` | 2764 | 命中 9 类（POLICY_CLAUSE / ATTENDANCE_RECORD / …） | ✅ 可用 |
| `affiliation-demo-v1` | 176 | **0 类**（SUBJECT / LEGAL_PERSON / ADDRESS / CONTRACT / INVOICE / VOUCHER / PHONE） | ❌ **必然空** |
| `None` | 8 | 0 类 | ❌ 空 |

根因：`TERMINAL_ENTITY_TYPES` 是**考勤本体**硬编码（`reasoning.py:98`，注释写着"换业务域时只改本元组"）。
⇒ **关联方域（PRD M4 的核心场景：A → 股东 → B 的疑点链）走不出多跳链**。这是本批次要修的。

## 2. 冻结：多跳答对率口径（plan §17.1 要求"先落文档"）

PRD 附录 C:293 原文：**多跳答对率 = 3 跳内问题正确回答数 / 总多跳问题数，准入 ≥ 0.80**。落地口径：

| 项 | 口径 |
|---|---|
| **分母** | 受控多跳问题集 N 题。每题登记三件事：① 期望答案要点（golden）；② **所需最少跳数**（≥2 才算"多跳"，1 跳问题不得充数——plan §17.3 明令"不得用单跳冒充多跳"）；③ 所属域 |
| **分子（三条全中）** | ① 未拒答；② `reasoning_path` 非空且 **hop 数 ≤ 3**（"3 跳内"的机械判据，取响应里的实际跳数）；③ 答案与 golden 一致 |
| **③ 怎么判** | **人工**比对（判分人 = 执行者，登记进 `integration-log.md`）。**不冒充机械判据**：语义正确性无法用子串匹配可靠判定，硬做就是给自己造一个好看的假数字（F3 / G5）。机械可判的只有 ①② |
| **载体** | 扩展既有 `backend/scripts/eval_controlled_qset.py`（它的覆盖率 / 拒答误伤口径已冻结在 v2-2026-09-26，另起一套评测器必然口径漂移） |
| **未达标的处置** | 按 plan §17.3 降级预案：保留 `*1..3` 能力，**把多跳答对率登记为 S13 实验观测项**，不得用单跳冒充 |

**本批次不做测量**：问答链路需要 **PG**（本机无 PG 服务，5432 未监听）⇒ 口径先冻结、代码先修域覆盖，测量与批次 A 的端到端验证一起在 PG 就绪后补（已在 `../Sprint10/integration-log.md` §4 登记）。

## 3. 裁决

| # | 裁决 | 判据 |
|---|---|---|
| **D-F** | 终点类型**按域登记**，不再写死考勤本体：新增域策略注册表（考勤 / 关联方两套），由本轮子图的实体类型**确定性选域**；**查不到所属域 ⇒ 不猜**，返回空策略（链取不到 = 空列表），而不是放宽成"任意类型" | 纪律 1「零假数据」：终点白名单的意义就是"链必须落在可核查落点上"，放宽成任意类型 ⇒ 随便走两跳 = 编链 |
| **D-G** | **不把跳数参数化**（plan §17.1 原文要求"跳数上限参数化"） | `_MAX_HOPS=3` 与 PRD「3 跳内」一致；参数化若无**真实消费方**就是无消费者配置，违反 `CODEBUDDY.md` R4（历史病例 `task_retry_multiplier`）。真出现"某个域需要 4 跳"的实测需求时再加，并同步给消费点 |
| **D-H** | 中途禁穿 hub（`EMPLOYEE`）的约束**保留**；关联方域的 hub 为 `None`（该域无"人人相连"的枢纽） | 考勤域实测：不禁 hub 会每条都出"员工→员工"的废链 |

- **不动 `_MAX_HOPS`**（D-G）；
- **不做前端**：推理链的前端绘制是批次 E2（S9.5 已规划），本批次只保证"关联方域也能出链"。
