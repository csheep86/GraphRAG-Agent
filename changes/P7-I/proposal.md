## 2. 做什么

1. 定义并登记「**L2 端到端**」的**精确边界**（从哪一步到哪一步：上传 → 解析 → 入图 → 检测 → 结果读回），先定义再跑。
2. 在同一批语料上真跑一遍端到端，出 L2 的召回 / 误报读数。
3. 把 L1 与 L2 的**差异**（若有）连同归因登记清楚——差异本身就是交付材料的一部分。

## 3. Non-goals（**改一条都要先回来登记理由**）

1. **不改算法，也不为「提高分数」而重跑**（这是**取证**批次，不是调优批次；调优须另立项并说明动机）。
2. **不动受控语料 seed、不改 `--gold v2` 判定口径**。
3. **不把 L2 失败改写成 L1 达标**（不许用分层口径打掩护）。
4. **不做结论性宣传口径**——报告的口径由 P8-Release 在客户材料里统一措辞。
5. **不动 C1 / C3**。

## 4. 出口判据

1. 「L2 端到端」的定义**落在正式文档里**（写明起止点与必经组件）。
2. 同一语料下 L2 的召回 / 误报读数可贴；与 L1 的差异有归因。
3. 若 L2 不达标 ⇒ **如实登记 FAIL**，并把这一事实同步到矩阵结算行（不得留 claim 空白）。
4. `pytest` 不降、三件套干净、CI 四 job 全绿。

## 5. 升级用户的四种情况

1. L2 不达标 ⇒ **立刻升级**（那更可能是产品缺陷而非评测口径问题），不要用分层口径掩盖。
2. 需要真 LLM 且会产生费用 ⇒ **先报预算再跑**（费用放行权在你）。
3. 定义边界时发现还有第三种中间层 ⇒ 停下回填分层裁决再开工。
4. CI 红且复核两遍仍红 ⇒ 带 job 名 + 失败行 + 归因。
