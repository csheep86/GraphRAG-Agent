## 🚨 无人值守执行规则（用户已预授权）

**本质**：这是 `executing-plans` 的**预授权变体** + 固定升级边界。

| 规则 | 要求 |
|---|---|
| **不索要过程性确认** | 会话开始**不复述摘要、不请求确认**，直接定位 `tasks.md` 第一个未勾选项开工 |
| **默认采纳建议项** | 文档里已有建议路径 / 默认档 / 既定口径的决策点（如 G-26 六条判据、受控函数三条约束、A4 逐点登记）⇒ **直接按建议执行并在 `integration-log.md` 登记事实**，不停下询问 |
| **立即验证并提交** | 每任务完成即跑其声明的验证（pytest / ruff / `export_openapi.py --check` / `check_seams.py`）；通过后**自动按 Conventional Commits 提交**，**无需请求** |
| **勾选并留痕** | 勾选 `tasks.md` 对应项；证据链写 `changes/P3/integration-log.md`（实测命令 + 输出摘要 + 关键发现） |
| **不降低验收标准** | 提前完成就提前验收，**不跳验收**；禁止静默降级 |
| **push 失败** | 重试**一次**；仍失败 ⇒ **登记在集成日志，继续推进**（已知间歇性网络问题），**不许**卡住产出刷第三次 |

### ⛔ 升级边界（**仅此 4 类停下找用户**，其余一律自主推进）

1. **裁决 1~5 被实现证伪**——例如保留 403 在技术上做不到、枚举租户性能不可接受、受控函数无法收敛
2. **需要新增 RLS 豁免表**——当前唯一豁免是 `roles`，扩大会直接撞 G-24 的三条断言
3. **必须改契约才能继续**——契约零漂移是硬要求，任何改动都属破坏性变更，须裁决
4. **修复超 3 轮仍红**——同一问题修了 3 轮门禁仍不过，停止并升级

> 其余任何情况（含"发现原计划不成立但文档里有建议项"）⇒ **按建议执行 + 登记**，继续推进。
> 升级时输出**升级报告**：触发类别、文档依据、已尝试动作、可选路径与建议。

### 输出格式

- 每完成一个任务：**一行进度**（任务号、结果、验证摘要、commit hash）
- 批次收束：**批次小结**（完成数 / 降级登记数 / 升级数）
- 触发升级：**升级报告**
