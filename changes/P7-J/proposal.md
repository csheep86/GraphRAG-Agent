## 2. 做什么（人做主体）

1. 生成/确认**签发环境**（离线机或密码管理器），把私钥迁移过去。
2. 从开发机**抹除**原文件，并确认回收站/备份里也没有。
3. 在 `tools/license/README.md`（或 ADR-0006 §证据节）登记：签发人 / 签发环境描述 / 迁移日期 / **联系方式不在仓库内**。
4. 校验：抹除后经理一个现有 client 仍能验签通过（公钥内置 ⇒ 不依赖私钥）。

## 3. Non-goals（**改一条都要先回来登记理由**）

1. **不重签已发出的 license**（若已发出，迁移会让它白名单失效——先确认有没有已发证件）。
2. **不改验签逻辑 / 不弱化机器指纹**。
3. **不把私钥放进仓库任何位置**（含加密压缩包 / base64 片段）。
4. **不做 KMS / HSM 接入**（那是量产阶段的事）。
5. **AI 不执行删除、不代填签发人姓名**。

## 4. 出口判据

1. 开发机 `private.pem` 已不存在（给出检索命令的输出）。
2. 签发环境可被指定的人复现，且鉴别能力不依赖当前登录会话。
3. 既有 `tests/test_license_guardrails.py` 8 条静态护栏 + `tests/test_license_fingerprint.py` 4 条**全绿**（本批不改它们）。
4. `git status` 无密钥相关痕迹；CI 四 job 全绿。

## 5. 升级用户的四种情况

1. 私钥文件已不存在（历史已处置）⇒ 报告 + 登记核实结论，本批可直接结案。
2. 发现私钥曾进入某一版镜像/包 ⇒ **立刻升级**（那是安全事件，可能要重出镜像）。
3. 存在已签发 license ⇒ 先确认换私钥对它们的影响再动。
4. 迁移路径需要你提供设备/介质 ⇒ 停下等你安排。
