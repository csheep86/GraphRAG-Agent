# P7-P · 首账号开户（F-P7N-2，方案 (a)）

> **日期**：2026-10-14 ｜ **来源**：`changes/P7-N/proposal.md` §5 第 1 条（已裁决推迟到 P7-H 之前）
> **一句话**：交付环境里那条"开第一个管理员"的命令 + 文档里的那一行。
> ⚠️ **这是交付前提**：没有它，客户拿到的系统**没有任何人能登录**。

## 1. 起点与坐标

| 项 | 坐标 |
|---|---|
| 缺口 | 客户环境**没有账号创建入口** —— `seed_dev_rbac.py` 只播 dev 默认 org，且要求 `ALLOW_DEV_ORG_HEADER`（生产本就为 false） |
| 已裁决方案 | P7-N §5 第 1 条 **(a)**：交付包里一条**幂等的一次性开户命令** + 一行文档，复用 `hash_password`（口令实现只允许一处，`seed_dev_rbac.py` 漂移过一次） |
| 部署形态（**本批的前提**） | 用户裁决（2026-10-14）：**一家一套** ⇒ 租户就是 `DEFAULT_ORG_ID`，**不需要建租户入口** |

## 2. 做什么

1. 新增 `backend/scripts/provision_admin.py`：幂等开户（建用户 + 授 admin + 卡 License 席位）。
2. `docs/deployment-spec.md` §4.2 安装步骤里插第 5 步（人跑的一次性命令）。
3. 两条单测钉住最危险的行为（重跑不改口令 / 席位不足拒绝）。

## 3. Non-goals

1. **不做租户创建入口**（`create_tenant`）—— 一家一套不需要；集团形态才需要，届时另立批次。
2. **不做改密 / 找回 / 首次登录强制改密** —— 那是产品功能，不是交付命令。
3. **不接外部身份源**（SSO / LDAP）⇒ P7-N 明写"目前无信息支持 ⇒ 不为它提前做设计"。
4. **不为 `--generate` 的口令做持久化** —— 它只出现一次，由人当场保管。

## 4. 出口判据

1. 开户后**真能登录**（`POST /auth/login` 拿 token + 带它调受保护端点得 200），错口令被拒。
2. 幂等：重跑不改口令；`--reset-password` 才改。
3. 席位不足 ⇒ 拒绝新建且不留下半个用户。
4. 文档 §4.2 有这一行；门禁不降、CI 四 job 全绿。

## 5. 升级用户的四种情况

1. 若客户要接外部身份源 ⇒ 停下报告（本地口令这条路径会被**架空而非继承**，P7-N §5 第 1 条）。
2. 若客户是集团形态（一套部署装多家公司）⇒ 停下报告：需要租户入口 + 集团视角，是新批次。
3. CI 红且复核两遍仍红 ⇒ 带 job 名 + 失败行 + 归因。
