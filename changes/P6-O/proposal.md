# P6-O · G-12 转正：让 variant 矩阵构建成为**常驻门禁**

> **日期**：2026-10-06 ｜ **上游**：`changes/P6-N/`（R22 已结案，剩余一层另立 R27）
> **关联需求**：DR-A1（variant 配置体系）/ DR-A3（构建期烘焙）｜ **护栏**：**G-12**
> **一句话**：A 组只剩 G-12 一条挂起。本批**不凑数、不放宽**，靠**第二个真实部署形态**
> 把它从 `xfail` 挂起转成常驻门禁。
>
> ⚠️ **开工前必读 §2（命名陷阱）与 §3 的 O-D2 前置** —— 这两处不看就动手，
> 会造出一个「CI 绿但 G-14 假红」或「写了没人读的字段」的结果。

## 2. ⚠️ 命名陷阱（本批最大的坑，**已查证**）

`_customer_tokens()`（`test_guardrails_delivery.py:32-54`）取**变体文件名的 stem** 与
`customer` / `customer_id` / `name` / `id` 字段值，对**基座契约做子串匹配**，
作为 G-14 的客户标识黑名单。

实测契约词频：**`default` 10 次 / `demo` 3 次 / `baseline` 0 次**
（前两者都是 OpenAPI schema 关键字与示例，**与客户无关**）。

⇒ **第二个变体绝不能叫 `demo` 或 `default`** —— 那会让 **G-14 结构性假红**
（这正是现有变体之所以叫 `baseline` 的原因，见 `deploy/variants/baseline.yaml` 头部注释）。

**机械验证（必做）**：候选名先过契约词频检查，**等于 0 才可用**：

```powershell
(Select-String -Path contracts/openapi.yaml -Pattern "<候选名>" -AllMatches).Matches.Count
```

## 3. 决策点（建议项 —— 无人值守下默认采纳；有异义按第 4 类情况升级用户）

| # | 决策 | 建议项 | 理由 |
|---|---|---|---|
| **O-D1** | 第二个变体叫什么 | **`internal-demo`**（**须先过 §2 的词频检查**；不为 0 就换名，不改 G-14） | 避开 G-14 假红；沿用 `baseline` 的做法（文件名 stem = `customer` 值） |
| **O-D2** | **真实差异落在哪个字段** | **`domain_profile`**（ADR-0007 §3.2 的字段） | 两个业务域 **attendance / affiliation 都真实入图**（两个 `kg_version` 都在库里）⇒ 差异是**实证的**，不是编的。⚠️ **前置见下** |
| **O-D3** | 判据做到哪 | **骨架阶段**（yaml 可解析 + 顶层是映射），**不**实现真实镜像构建 | 真实构建依赖 deploy 侧构建流程落地，属另一批；骨架阶段不得宣称"构建成功已验证" |
| **O-D4** | `base_ref` 写什么 | 跟随 `app_version`（当前 **1.6.0**），**机械核对**而非手写 | 手写会漂；`baseline.yaml` 现在就是 `v1.6.0` |

### ⚠️ O-D2 的前置（不做完不许写字段）

CODEBUDDY.md「功能预留原则」第 6 条是硬规则：**无消费者的配置不得提交**
（历史病例：`task_retry_multiplier` 声明存在、退避路径从未读取）。

⇒ **T1 必须先查 `domain_profile` 有没有代码读取它**。
- **有消费者** ⇒ 按 O-D2 写；
- **无消费者** ⇒ **不许写这个字段**（那会造出一个"看起来有差异、实际没人读"的假差异），
  改用别的**有实证**的差异维度；若确实需要先建消费者 ⇒ **那属于另一批**，升级用户。

## 4. Non-goals（10 条，**编号列表** —— S1 只读得到这种格式）

1. **不放宽** G-12 的启用条件（不得改成 ≥1）。
2. **不捏造客户**：第二个变体必须对应一个**真实存在**的部署形态。
3. **不实现真实镜像构建**：骨架阶段只判「yaml 可解析 + 顶层是映射」。
4. **不改 G-14 的子串匹配逻辑**（P2.5 裁决；改它等于让 G-14 失去意义）。
5. **不动契约**：变体不进 `contracts/openapi.yaml` ⇒ `export_openapi.py --check` **零 diff**。
6. 不加任何 `settings.*` 配置项。
7. 不动 compose 的 `image:` / `build:`（G-19 已生效，别顺手动）。
8. 不新建 / 不改 CI job（如需，另开批次）。
9. **不写无消费者的字段**（见 §3 O-D2 前置）。
10. 不顺手修其它遗留；**不宣称**"多客户交付已验证"（绿灯只代表机制可跑）。
