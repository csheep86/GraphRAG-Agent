# P6-I · 决策文档：rubric「要点全覆盖」要不要改成分层计分

> **日期**：2026-10-05 ｜ 前序：`P6-H`（v4 40 题，C1 = 0.0294）
> **性质**：**决策文档，不是实施计划** —— 需要你拍板后才动手
> **一句话**：改 rubric 会让 C1 从 **2.94% 抬到约 8.8%**，量级足以影响决策 ⇒ **必须先于 ⑤ 校准定下来**；
> 但抬升的原因里有一部分是「救回了图侧部分答对的题，而基线侧整题炸掉的救不回来」
> ⇒ **这是陷阱，必须先讲明白再决定**。

---

## 1. 为什么现在写这份

P6-H 出数后我提示过：当前 rubric（要点全覆盖才 true）可能是 0.0294 的部分成因。
这话不能停在提示层——因为**改 rubric 会改变 C1 的值**，而 ⑤ 要校准的阈值是在**某套 rubric 之上**标定的：

> **两个自由度只能串行**：先定 rubric，再标定阈值。
> 若反过来（先标定阈值、后改 rubric），标定成果立刻作废；若同时进行，则谁也说不清校准出来的
> 阈值反映的是**系统能力**还是**判分口径的宽容度**。

所以这份必须在 ⑤ 之前有结论。

## 2. 现状：rubric-v1 到底怎么判

`MANIFEST.json` 的 `rubric-v1`（原样抄录）：

| 项 | 规则 |
|---|---|
| ① | 拒答判定与 `should_refuse` 一致 |
| ② | 答案覆盖 `expected_points` 的**全部**要点 |
| ③ | 无与语料矛盾的事实（幻觉） |
| 判定 | ①②③ 全满足 ⇒ true；任一不满足 ⇒ false；未判分 ⇒ null（**不入分母**） |

⇒ 性质：**二元 · 等题权 · 要点零容忍**。

## 3. 实测暴露的三个问题（用 v4 的真实数据）

### 3.1 ⚠️ 我出题时的过错：`expected_points` 粒度不均 ⇒ 题权重根本不等

v4 的实际要点数分布：

| 要点数 | 题号 |
|---|---|
| **1** | Q8, Q10, Q13, Q14, Q22, Q25, Q26, Q32, Q36, Q39, Q40（**11 题**） |
| **2** | Q1, Q2, Q3, Q5, Q6, Q7, Q9, Q11, Q12, Q15~Q21, Q23, Q24, Q27~Q29, Q31, Q34, Q35, Q38（**24 题**） |
| **3** | Q4, Q33, Q37 |
| **4** | Q30（外勤证据优先级，须列全四类） |

⇒ **Q30 要答对 4 条才算过，Q8 答对 1 条就过，而两题在 C1 里权重相同**。
这是**出题人（我）的粒度选择直接决定题目难度** —— 必须登记的设计缺陷；
且它**独立于**要不要改 rubric：就算维持现状，也该把粒度做一次拉平审视。

### 3.2 「补充要点」导致动辄 false（Q5 / Q7 是典型）

| 题 | expected_points | 图侧实测 |
|---|---|---|
| Q5 | [每月加班不得超过 36 小时]／[**依据**劳动法第四十一条] | 答出了 36 小时，**漏了法律出处** ⇒ 现状判 **false** |
| Q7 | [适用不定时工作制]／[已**履行审批**] | 答出了不定时工作制，**漏了已审批** ⇒ 现状判 **false** |

⇒ 这两题的**主答案都答对了**，false 是因为少说了「依据是哪条法律」「是否走过审批」。
这种要点本质是**补充信息**，与「把工时制答错」的严重性完全不同，却在二元计分下等同。

### 3.3 二元计分把信息丢光了

Q30 答对 3/4 类证据 与 答对 0/4 类，都是 false ⇒ 可用信息全部丢失。

## 4. ⚠️ 改 rubric 会让谁受益（**这份文档最重要的部分**）

先看两侧 false 的**性质**（v4 实测）：

| | 图侧 false（5 条） | 基线侧 false（6 条） |
|---|---|---|
| 构成 | Q5、Q7：**缺补充要点**（部分答对）<br>Q22、Q26：整题答不上（0 覆盖）<br>Q20：拒答 | Q12/Q35/Q36/Q37/Q38：**整题拒答**<br>Q34：答非所问（自陈未找到，要点 0 覆盖） |
| 分层后能否被救回 | **Q5 / Q7 能**（其余三条是 0 覆盖，怎么分层都是 0） | **一条都救不回来** |

⇒ **分层计分几乎只会让图侧涨分**。

原因很直白：基线的失分形态是「**整题拒答 / 整题答非所问**」——那是真的零覆盖，任何部分计分都救不了；
而图侧的失分形态是「**答对了主体、漏了补充**」——这部分恰恰是分层计分能救的。

> 所以：**放宽 rubric ⇒ C1（图相对基线的增益）必然变好看**，且变好看的来源里有一部分是
> 计分口径的宽容度，而**不是系统能力的提升**。
> 这不是说不能改，而是：**改的理由必须是「现在的 rubric 系统性低估了正确答案」，
> 不能是「现在的数字不好看」。**

### 估算各方案下的 C1（**基于已知 false 明细推算，尚未重判**）

基线侧在所有方案下都近似不变（34/40 = 0.85），故只需看图侧：

| 方案 | 图侧 | baseline | C1 = (图 − 基) / 基 |
|---|---|---|---|
| **现状** | 35/40 = 0.875 | 0.850 | **2.94%** |
| 只救 Q5 / Q7 | 37/40 = 0.925 | 0.850 | **8.82%** |
| 再多救 1 题 | 38/40 = 0.950 | 0.850 | **11.76% ⇒ 越过 10% 阈值** |

⚠️ **C1 是否达标悬于 1 道题的判罚**：差一题就从「差 7pp」变成「达标」。
在 40 题上单题灵敏度是 2.5pp，但**经增益公式放大后**（除以基线 0.85）单题影响约 **2.9pp**
⇒ **阈值的可信度取决于 rubric 的可信度**。

## 5. 四个候选（含「不改」）

| | **0. 维持现状** | **A. 连续要点加权** | **B. 比例阈值保二元** | **C. 要点分级 core/secondary** |
|---|---|---|---|---|
| 规则 | 全覆盖才 true | `score = 覆盖数/n_i`，accuracy = 均值 | 覆盖 ≥ X% 要点 ⇒ true | 覆盖**全部 core** ⇒ true；secondary 缺失**不扣主分** |
| 能否救 Q5/Q7 | 不能 | 能（各得 0.5） | **X ≤ 50% 才能** | **能**（法律出处、审批状态标成 secondary） |
| 对 Q30（n=4）是否公平 | 偏严 | 答 3/4 = 0.75，合理 | X=60% 时答 2/4 即过 ⇒ 偏松 | 取决于 core 怎么标，**由语义决定而非数量** |
| 出题粒度能否操纵结果 | 能（写细即难） | **能，且最直接** | 能（数量决定 X 的含义） | **较难**：分级是显式的，写进 JSON 可复核 |
| 额外收益 | 无 | 分数连续可画曲线 | 无 | **可派生子指标**：secondary 覆盖率 =「答案完整度」，不污染主判据 |
| 主要成本 | 0 | **要点级重判 80 条** | 同左 | 同左 + 给 40 题标注 core/secondary |

⇒ **A 的直接问题**：出题人握着分数刻度。§3.1 已证明粒度确实不均 ⇒ 这不是假想风险。
⇒ **B 的问题**：同一个 X 对不同 `n_i` 的题含义完全不同（2 要点题漏一条 vs 4 要点题漏两类证据）。

## 6. 我的建议（明确立场）

1. **维持「二元」主判据语义不变，不采纳方案 A**。理由：连续分数与 `expected_points` 的写法强耦合，
   而 §3.1 已证明粒度不均 —— 在这个前提下引入连续分数，等于把分数刻度交给出题人的笔。
2. **若要改，采纳方案 C（core / secondary 分级）**。它恰好对症 §3.2：
   Q5 的 core 是「36 小时」、Q7 的 core 是「不定时工作制」；法律出处与审批状态是 **secondary**。
   这个区分是**语义判断**且要随判定说明写进 JSON ⇒ **可复核**，不像数量阈值那样靠运气。
3. **不论改不改，§3.1 的粒度不均都应登记为待修**：拉平 `expected_points` 的写法标准
   （例如统一「每题核心答案 ≤ 2 条，补充信息单列」）——**这比改 rubric 更基础**。
4. **顺序：必须先有这份结论，再进 ⑤**。否则 ⑤ 标出来的阈值只在新 rubric 上成立，
   rubric 一动就得重标。

## 7. Non-goals（**冻结；若动手则 drift S1 会逐条读出**）

1. **不校准任何阈值**（属 ⑤；本批只决定「用什么尺子量」）；
2. **不改 C1 / C2 判据的计算公式**（仍是 `(图 − 基) / 基`）；
3. 不动题面、不动 40 题的组成（`should_refuse` / 题数一律不变）；
4. 不动 `C2` 与其它判据当前的实现；
5. 不改 `rubric` 的第 ①③ 条（拒答一致性、无幻觉）——**只讨论第 ② 条**（要点覆盖）；
6. **不为了「让 C1 达标」而放宽标准**：任何改动必须有**独立于数字**的理由（见 §4 引述）；
7. 不顺手修 H6 403 / 制度入图器自检恒 FAIL / P7-B / G-12 / MANIFEST 语料统计过期；
8. 不改检索 / prompt / 拒答判定（那是被测链路）；
9. 若选 A/B：**不得**同时调整选题（不许既改计分又选题，那会变成拟合）。

## 9. 前置验证怎么做（D3 若同意）

```
V1  给 40 题标注 core / secondary（先存 rubric-v2 草案，不改其它任何东西）
V2  要点级重判：11 条 false + 9 条随机 true（两侧共 40 条尺在一쳇之内）
V3  用公式回算 C1，与 §4 推算对照 ⇒ 验证偏差是否 < 1.5pp
V4  若一致 ⇒ 全量重判（80 条）并正式落成 rubric-v2；若不一致 ⇒ 重新审视
```

> **为什么要有 V1–V3 这一步**：全量要点级重判的成本约等于重做一次 P6-H 的判分。
> 在没验证「分层到底能不能改变结论」之前就投进去，是本末倒置。
