# P7-O · P7-H 的两个硬前置修复（恢复落点错位 / 幽灵版本对齐）

> **日期**：2026-10-14 ｜ **来源**：`docs/drills/restore-drill-20261013.md` §发现 4 与 §8.3
> **一句话**：把上次恢复演练里那两处**会让 P7-H 白做**的缺口先修掉。
> ⚠️ **本批是 P7-H（升级 + 回滚演练）的硬前置**：不修，回滚后的 §6.2 必然 FAIL，
> 且"恢复到目标环境"这件事本身不成立。

## 1. 起点与坐标

| 缺陷 | 坐标 | 上次演练的实证 |
|---|---|---|
| **落点错位** | `restore.py::apply_restore` —— 未给 `--storage-root` / `--license-file` 时退回 `settings`（**本机**）路径 | 演练的 storage / License 被写到**宿主**，目标栈里没有 ⇒ 演练 C 项"没恢复到目标环境"**不达标** |
| **幽灵版本** | `app/services/backup.py::evaluate_version_consistency` ⇒ `ghost_version` | §6.2 **FAIL**，退出码 2「不许启动」；PG active `20261012T064951Z-inc-569555ad` 在图库无镜像节点 |

## 2. 做什么

1. **落点**：不给落点就 **SKIP**，绝不落本机（与脚本别处"宁可 SKIP 不猜"同一套纪律：
   `--target-db` 不猜、`.env` 不自动回写）。
2. **幽灵版本**：以 **PG 真源为准**补一次图库镜像 —— 用**已存在**的
   `sync_kg_version_mirror`，**不新建入口**（这正是 P7-G 裁决 A 里写的"补偿办法"）。

## 3. Non-goals

1. **不顺手清理 dev 图库里的历史脏数据**（248 个测试跑批留下的镜像）—— 那是另一码事，见集成日志 §4。
2. **不改 §6.2 的判定口径**（ghost 依旧 FAIL，只是本机已不再处于该状态）。
3. **不动 PG 真源**（不新增 / 不回退 `kg_versions` 记录）。

## 4. 出口判据

1. 未给落点 ⇒ storage / license 落成 `SKIP` 且**不写本机**；给了 ⇒ 落到指定处（有读数）。
2. §6.2 由 `ghost_version` **FAIL** 转为 `pg_graph_consistent` **OK**（有读数）。
3. `pytest` 不降、ruff / format / 契约 / 接缝四件套干净、CI 四 job 全绿。

## 5. 升级用户的四种情况

1. 若补镜像要求**新建**同步入口 ⇒ 停下报告（会撞 P6-V3 裁决）。**本次未触发**：
   用的是 P6-X2 已实装的 `sync_kg_version_mirror`。
2. 落点改动若导致既有演练留证口径失效 ⇒ 登记，不改判据。
3. CI 红且复核两遍仍红 ⇒ 带 job 名 + 失败行 + 归因。
