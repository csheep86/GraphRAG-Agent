# P7-R · 答案稳定性治理（P7-K 出口判据 1 的否证后续）

> **日期**：2026-10-14 ｜ **来源**：[`changes/P7-K/integration-log.md`](../P7-K/integration-log.md) §10
> **一句话**：先**测量**「同一份代码、同一份数据，连跑两次答案差多少、差在哪」，
> 再据此决定治理路线是**钉住输出**还是**改判分口径**。
> ⚠️ **本批的前置事实**：P7-K 出口判据 1「连跑两次答案逐字一致」已被实测**否证**
> （`--compare` EXITCODE=1，图侧 13/40 不同）。本批**不是去把那个数跑出来**，
> 而是回答「它为什么不可达，以及该怎么办」。

## 1. 起点与坐标（全部为当日实测，不是推断）

### 1.1 由读数直接得出的定性（**这是本批的立足点**）

> **漂移不在检索侧，在生成侧的措辞。**

依据是两条率的落差：`citations` 一致率 **0.900** > 答案一致率 **0.675**。
若证据换了，两者会一起掉；现在只有措辞掉 ⇒ **证据没换，是模型在同一批证据上每次说法不同**。

⚠️ 这句话必须写进 proposal，因为它决定了后面做什么：
**去改检索是白费劲**（它本来就稳），**要治的是生成口径**。

## 2. 做什么

1. **做一个可复跑的稳定性探针**（¥0 起步）
   同一批题连跑 **N=3** 次，逐题比对，产出三个率：**答案逐字一致率 /
   要点覆盖一致率 / `citations` 一致率**（含 n 与差异题号清单）。
   ⇒ 关键：**一条命令、输出格式固定、可重复跑**，否则后面没法判断"改了有没有效"。

2. **给差异分类并给出占比**
   - (a) **证据不同**（`citations` 变了 ⇒ 检索漂）
   - (b) **同证据不同措辞**（`citations` 相同、答案不同 ⇒ 生成漂）
   - (c) **拒答翻转**（refused 状态变了）
   ⇒ 这一步会**机械地**印证或推翻 §1.1 的定性。

3. **可控因子实验（逐项留读数）**
   逐项试，每试一项登记一次一致率：
   `seed`（供应商是否支持）／ `top_p=0` ／ **串行 vs 并发** ／ 批处理影响。
   ⚠️ 不许"试了不记录" —— 试而不记，等于没试，且事后无法复盘。

4. **出结论，交裁决**
   - 若有某一项能把一致率钉到 ≈100% ⇒ 写进评测口径（**路 A：钉住输出**）；
   - 若试尽可控手段仍有漂移 ⇒ **如实登记「逐字复现在本架构上不可达」**，
     并给出 **路 B：判分口径从「逐字一致」降为「要点覆盖一致」**。
     ⚠️ 路 B **属 rubric 变更**，须用户裁决；本批**不擅自改 rubric-v2**。

## 3. Non-goals（**改一条都要先回来登记理由**）

1. **不改 rubric-v2、不新增补充口径** —— 路 B 若被采纳 ⇒ **另开一批执行**，
   本批只负责把结论和建议摆在桌面上。（继承 P7-K 边界第 5 条）
2. **不动 C1 / 多跳阈值**（阈值仍 provisional；TBD-7 归 P7-F）。
3. **不为「让数字好看」挑一轮好的留下** —— 结果变差必须如实登记（继承 P7-K 边界第 6 条）。
4. **不重判 86 题**（P7-K 边界第 1 条继续有效；本批**只测量、不重判**）。
5. **不改产品检索主链路**（撞 P6-V5 版本语义裁决的风险区）。
6. **不把「40 题零差异」当成唯一成功标准** ——
   若证据侧稳定而措辞侧**不可能**稳定，那么**如实说出这一点**才是本批的成功；
   把一条不可达的判据挂在那里，等于让 P8-Release **永久等待一个不会来的数字**。

## 4. 出口判据

1. 稳定性探针**可复跑**（一条命令、固定输出格式），且至少跑过 **N=3** 次。
2. 给出三个读数（含 n）：**逐字一致率 / 要点一致率 / `citations` 一致率**。
3. 差异被分成 (a) 证据不同 / (b) 同证据不同措辞 / (c) 拒答翻转 三类，并给出各自占比。
4. 可控因子实验**逐项留读数**，结论明确写成「哪一项有效」或「都无效」。
5. 给出 **A / B 二选一的明确建议**；若建议 B ⇒ 注明须用户裁决（rubric 变更）。
6. `pytest` 不降、三件套干净、CI 四 job 全绿。

## 5. 升级用户的四种情况

1. **实验表明需要改 `ChatOpenAI` 的采样/调用参数（属产品生成主链路）** ⇒ 停下报告
   （可能撞 P6-V5 或生成口径裁决）。
2. **需要动判分材料的口径（路 B）** ⇒ 停下报告（rubric 变更，须用户裁决）。
3. **多项因子试尽后一致率仍 < 100%** ⇒ 停下报告，如实登记「逐字复现不可达」，
   由用户在 **「接受要点级复现」** 与 **「整轮重判」** 之间裁决。
4. CI 红且复核两遍仍红 ⇒ 带 job 名 + 失败行 + 归因。
