## 4. Non-goals（**本批不做**）

- **不实现 M6**：冷启动 GUI、人工校正界面（merge/split/rename）、增量重算、`cost_metrics` 落库与仪表盘 —— 全部归 **P5-M6 批次**
- **不做 PoC 之外的 M6 代码**：F1 只验证「LLM 建议 → 候选」这条通路是否走得通
- **不改 `m6` §1~§6 的实质内容**（§10 明确定稿不重写）；只做勾选、删 §7、改版本行
- **不动 ADR 原文**（守 **R5**）；差异与遗留登记在本批日志
- **不做 P2-B（RBAC）/ P2.5 / P3** —— 与定稿批次无关，不混进来
- **不调阈值 / 不调 prompt**：`kg_extraction_v1.md` 一字不改（PRD §7 / H9）
- **不做 C1–C3 评测脚本**（只定方案，另立 F4 批次）

## 5. 决策点与建议（**默认采纳建议项**）

| # | 决策点 | 建议 | 理由 |
|---|---|---|---|
| **D1** | PoC 的 LLM 调用怎么跑 | **默认用可注入的 fake provider**（CI 可跑、可复现、零成本）+ **另做一次真 LLM 留证** | 实测结果反哺规则要求真机证据；但 CI 与回归不能依赖余额（v1.3.0 曾记余额 ¥8.37，LLM 预算是本仓已知约束） |
| **D2** | 契约先行怎么做 | **先写 7 个端点的 501 占位骨架**再导出契约 | 契约是**代码导出**的，手改 yaml 会被 `--check` 判红；501 占位有先例（S1 的 `graph/query` 501）。另一种「把④推迟到实现批次」= **放宽硬闸门**，不采纳 |
| **D3** | F4（评测方案）是否并入本批 | **不并**，另立一批 | 摊太大（`check_session_drift` S2 要拦的）；且 F4 需产品口径（TBD-7 阈值），与定稿性质不同 |

## 6. 风险

| # | 风险 | 处置 |
|---|---|---|
| **RK-F1** | **PoC 跑不通**（LLM 建议质量 / 参数化路径不通） ⇒ spec 要改 | 先跑 F1 再定稿；不通即**升级用户**，按 R2 评估改 spec 或显式降级，**不许**先定稿再返工 |
| **RK-F2** | 501 占位端点被误读成「M6 已实现」 | 骨架**只返回 501** + 日志/契约描述写明"未实现"；CI 与 `check_startup_readiness` 不因此产生假的绿灯 |
| **RK-F3** | 契约新增 7 个端点 ⇒ 前端 TS 与 mock 需同步，否则漂移门禁红 | F2 内跑 `gen:api` + `git diff --exit-code`；前端只同步类型，**不**补业务实现 |
| **RK-F4** | 定稿后 P5 实现时又要改 spec（如 `applied` 落地细节） | 属正常；按 **R5** 登记在 P5 批次日志，**不**回改 v1.0 的历史结论 |
