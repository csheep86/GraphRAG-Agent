# 技能名称：writing-plans（编写实施计划）

## 用途
把需求草案或 `changes/<id>/proposal.md` 转化为一份可执行、可验证、可勾选的实施计划，明确每一步做什么、改哪些文件、如何验证。计划是后续 executing-plans 技能的输入。

## 触发条件
- brainstorming 完成且方案已获用户确认。
- 用户要求为某功能 / 某变更编写实施计划或任务拆解。
- OpenSpec 变更提案已定稿，需要生成 tasks。

## 执行步骤
1. **收集上下文**：读取需求草案、相关 `specs/`、`contracts/openapi.yaml`、涉及的 `frontend/` 与 `backend/` 代码现状。
2. **确定任务粒度**：每个任务控制在可独立验证的粒度（单一职责，一次提交可完成）。
3. **排序与依赖**：按"契约 → 后端 → 前端 → 测试 → 验证"的项目铁律排序，标注任务间依赖。
4. **明确验证方式**：每个任务写清验证手段（运行哪个测试、检查什么输出）。
5. **标注角色边界**：每个任务标注所属角色（A=前端 / B=后端 / 架构师=契约与规格）。
6. **写入文件**：使用 `specs/_template/tasks.md` 的结构，产出 `changes/<id>/tasks.md`。
7. **自查**：检查计划是否覆盖 proposal 中的所有 What Changes 项；是否包含契约同步步骤；是否预留了接口对齐清单核对点。

## 输出格式
基于 `specs/_template/tasks.md` 的编号 checklist：
- 按阶段分组的任务列表（每项含：任务描述、涉及文件、角色、验证方式、依赖）
- **风险与未决项**清单
- **明确不做**（Non-goals）清单
