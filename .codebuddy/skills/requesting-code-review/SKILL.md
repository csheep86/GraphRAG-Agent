# 技能名称：requesting-code-review（发起代码审查）

## 用途
在功能完成、自我验证通过后，主动发起结构化的代码审查请求，并把审查反馈转化为明确的修改清单，保证变更质量达到项目规范。

## 触发条件
- 某功能 / 任务组 / 分支实现完毕且通过 verification-before-completion。
- 用户要求 review、审查、"看看有没有问题"。
- 变更同时触碰了 `contracts/`、`frontend/`、`backend/` 中多个目录（必须审查）。

## 执行步骤
1. **准备材料**：整理变更摘要（改了什么、为什么）、涉及文件清单、验证结果（测试输出）、相关契约 diff。
2. **发起请求**：向审查者（子代理或用户）提供上述材料，并附上审查要点：契约一致性、Pydantic 校验、错误响应结构、异步任务重试、限流、日志脱敏、Prompt 是否硬编码、测试覆盖（参考 `.codebuddy/rules/model-decision/code-review.md`）。
3. **等待反馈**：不抢答、不辩解，完整接收反馈清单。
4. **分级处理**：将反馈分为"阻塞"（必须改）与"建议"（可讨论），逐项处理阻塞项。
5. **回复闭环**：每条反馈说明处理结果（已修复 / 有理由不改 / 移入后续任务），必要时请求复审。
6. **同步契约**：修复若涉及接口变更，先回到契约同步铁律流程。

## 输出格式
- **审查请求**：变更摘要 + 文件清单 + 验证结果 + 审查要点
- **反馈处理表**：反馈 → 严重级别 → 处理结果
- **复审结论**：是否全部阻塞项关闭
