# 技能名称：verification-before-completion（完成前验证）

## 用途
防止"幻觉式完成"：在说"做完了"之前，用可执行的证据证明需求被满足、代码可运行、测试通过、契约一致。宁可多花一分钟验证，不可凭印象宣布完成。

## 触发条件
- 即将向用户汇报某任务 / 功能 / 变更"已完成"。
- 一个分支的所有计划任务勾选完毕，准备收尾。
- 修改了接口、契约、Prompt 或异步任务后准备交付。

## 执行步骤
1. **对照原始需求**：逐条核对用户需求 / 计划任务，确认无遗漏项；有遗漏则补做或明确声明未做。
2. **编译与构建**：后端 `uv sync` + import 检查；前端 `npm run build`（或 lint），确保无编译错误。
3. **运行测试**：运行相关测试（`tests/unit|integration|e2e`），确认全绿；记录通过数。
4. **契约一致性**：若涉及接口，确认 `contracts/openapi.yaml`、前端生成类型（`npm run gen:api`）、后端 Pydantic 模型三方一致。
5. **清理痕迹**：删除调试代码、临时文件、被注释掉的死代码、无用的 `.gitkeep`；检查未使用的导入。
6. **诚实汇报**：将验证结果与任何已知限制一并列出，不确定的地方明说"未验证"。

## 输出格式
- **验证清单**：核对项 → 结果（通过 / 失败 / 未验证）
- **测试结果**：运行命令 + 通过 / 失败统计
- **已知限制**：明确列出未验证或依赖外部条件的项
- **结论**：是否可以宣称完成
