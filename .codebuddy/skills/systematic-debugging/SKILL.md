# 技能名称：systematic-debugging（系统化调试）

## 用途
用假设-验证的科学方法定位问题根因，杜绝"随机改动碰运气"式修复，并沉淀调试证据供后续同类问题参考。

## 触发条件
- 测试失败、接口报错、异常堆栈、行为与预期不符。
- 第三方组件（MinerU / LangExtract / LangChain 等）输出与官方文档不一致。
- 用户报告 bug 或要求排查问题。

## 执行步骤
1. **稳定复现**：先构造最小可复现案例（最小输入、最小代码路径），确认复现条件稳定。
2. **收集证据**：读取 loguru JSON 日志，按 `trace_id` 追踪完整调用链；检查各环节输入输出。
3. **形成假设**：列出 2-3 个候选根因，按可能性排序，每个写明"如果成立，应当观察到什么"。
4. **逐一验证**：用日志、断点或临时探针验证 / 排除假设，一次只验证一个，记录证据。
5. **定位根因**：锁定被证据支持的根因；若全部排除，回到步骤 2 扩大证据面。
6. **最小修复**：写复现测试（TDD 的红），实施最小修复使其变绿。
7. **举一反三**：检查同类代码是否存在相同问题；若为第三方对接问题，把实测结论沉淀到 `docs/`（实测结果反哺规则）。

## 输出格式
- **问题陈述**：现象 + 复现步骤
- **证据链**：trace_id、关键日志片段、每步验证结论
- **根因**：一句话 + 支撑证据
- **修复**：改动文件清单 + 复现测试名 + 验证结果
