# 技能名称：subagent-driven-development（子代理驱动开发）

## 用途
把"调度"与"执行"分离：主代理负责理解需求、拆解任务、分发与验收；子代理（Task 工具派生的 code-explorer 等）负责具体探索或实现。降低主上下文占用，提高并行效率。

## 触发条件
- 任务需要在多个文件 / 多个模块间并行推进。
- 需要大规模代码探索（超出单次检索能覆盖的范围）。
- 实现、审查、验证需要由不同"视角"独立完成。

## 执行步骤
1. **拆解**：把工作切成可独立交付的子任务，每个子任务写清：目标、涉及目录、输出物、验收标准。
2. **分配角色**：探索类交给 code-explorer 子代理（只读）；实现类按角色隔离原则分派（前端任务与后端任务分开）；审查类在实现完成后另派。
3. **派发**：用 Task 工具并行派发互不依赖的子任务；有依赖的按拓扑顺序串行派发。
4. **验收**：每个子代理返回后，主代理核对其输出是否满足验收标准（引用 verification-before-completion 的方法抽查），不满足则退回重做。
5. **整合**：汇总各子任务结果，处理交叉影响（如契约同步），保持全局一致性。
6. **不越界**：主代理不替子代理写代码细节，子代理不擅自扩大范围。

## 输出格式
- **任务分派表**：子任务 → 执行者 → 依赖 → 状态
- **并行执行说明**：哪些子任务并行、哪些串行及原因
- **整合结论**：各子任务验收结果与最终交付状态
