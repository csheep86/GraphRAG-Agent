# 技能名称：brainstorming（头脑风暴）

## 用途
在进入实现或规格编写之前，与用户一起把模糊的想法变成清晰、可验证的需求：明确目标、边界、约束与候选方案，最终产出一份可供评审的需求草案。本技能强调"先想清楚再动手"，与项目的 SDD（规格驱动开发）流程衔接。

## 触发条件
- 用户描述了一个新功能 / 新模块 / 新 MVP 的想法，但需求细节不完整。
- 用户使用"帮我想想 / 头脑风暴 / 评估一下 / 这个功能怎么做"等表述。
- 任务的实现方式存在多种明显不同的候选方案，需要先探索再决策。

## 执行步骤
1. **复述目标**：用自己的话复述用户想要的东西，请用户确认。
2. **澄清提问**：一次性集中提问（避免多轮追问），覆盖：目标用户、输入输出、边界（Non-goals）、与现有 `specs/`、`contracts/` 的关系、验收标准。
3. **梳理约束**：对照 `CODEBUDDY.md` 项目规则，列出本次需求涉及的硬约束（契约同步、异步任务、存储、安全等）。
4. **生成候选方案**：给出 2-3 个可行方案，每个说明优缺点、工作量估计与风险。
5. **给出推荐**：明确推荐一个方案并说明理由，等待用户选择。
6. **产出草案**：用户确认后，将结论整理为需求草案（可直接喂给 `specs/_template/proposal.md`）。

## 输出格式
- **需求摘要**（3 句以内）
- **澄清问答记录**（问题 → 用户答复）
- **候选方案对比表**（方案 / 优点 / 缺点 / 风险 / 估计工作量）
- **推荐方案及理由**
- **后续动作**：建议进入 writing-plans 或直接创建 `changes/<id>/proposal.md`
